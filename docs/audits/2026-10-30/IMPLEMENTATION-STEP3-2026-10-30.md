# STEP 3 — 백과·검색 탐색 복귀 완료

날짜: 2026-10-30 (Asia/Seoul)  
기준 계획: [UI/UX 개선 실행안](../2026-10-29/UIUX-STEP-BY-STEP-2026-10-29.md)  
이번 작업: STEP 3의 잔여 항목 UX-11. 이전에 구현한 UX-10·12·13도 연결 흐름을 재확인했다.

## 달라진 동작

| 사용 흐름 | 반영 내용 |
|---|---|
| 백과 → 다른 하단 탭 → 백과 | 선택한 월령·주제, 펼친 가이드와 읽던 위치 복원 |
| 가이드를 읽는 중 새로고침 | 지연 로딩된 본문과 펼침 상태가 준비된 후 읽던 문단 위치 복원 |
| 월령·주제 변경 → 뒤로/앞으로 | 월령·주제를 URL 이력으로 이동. 각 월령의 펼친 상태가 섞이지 않음 |
| FAQ 검색·답변 → 다른 탭 → 복귀 | 검색어·주제·분류·펼친 답변과 읽던 위치 유지 |
| 검색 목록 → 원문 → 검색 결과로 | 검색어·대상 월령·목록 위치 복원. 원문을 열었던 이력이 있으면 해당 목록으로 뒤로 이동 |
| 백과에서 검색 → 이전 화면으로 | 검색을 시작한 백과 주제·월령으로 복귀. 외부/잘못된 복귀 주소 거부 |

현재 UI 디자인은 유지했다. 탐색 상태는 임시 세션 캐시에 최대 80개 화면까지 보관한다. 아기·월령·주제·검색 조건별로 구분하며, 성장·접종·발달 관찰 기록이나 클라우드 데이터는 변경하지 않는다. 저장 공간이 차거나 차단돼도 현재 화면의 읽기 조작은 메모리에서 계속 동작한다.

## 고친 원인

1. `/encyclopedia`에 복귀할 때 기본 월령/주제가 저장된 마지막 맥락을 덮어쓰던 문제를 수정했다. 복귀 주소를 먼저 결정한 후 읽기 상태를 등록한다.
2. 가이드 청크가 준비되기 전에 스크롤 복원이 끝나던 문제를 수정했다. 펼침 상태가 적용된 본문을 기다리고, 문단 기준 위치도 함께 복원한다.
3. 이전 화면의 정리 작업이 새 화면의 스크롤 0을 저장하던 경쟁 조건을 차단했다.
4. 읽기 위치를 관리하는 경로에서 Next.js의 기본 스크롤 초기화가 복원과 충돌하지 않도록 연결했다.
5. 검색 초기 로컬 결과와 최종 결과가 서로 다른 정렬을 사용하던 문제를 수정했다. 온라인 결과가 합쳐지는 동안에도 읽기 복원과 사용자의 직접 스크롤을 구분한다.
6. 검색 결과에 돌아올 때 검색창 자동 포커스로 위치가 이동하지 않도록 했다.

## 검증

| 검사 | 결과 |
|---|---|
| `npm run lint` | 오류·경고 없음 |
| `npm run check:navigation` | 새 회귀 검사 10개 통과 |
| `npm run check:ux` | 기존 기록·날짜 회귀 검사 13개 통과 |
| `npm run build` | TypeScript 포함 프로덕션 빌드 통과 |
| 브라우저 | 실제 390px에서 탭 복귀·새로고침·검색 원문 복귀·월령 뒤로/앞으로·FAQ 검색 복원 확인 |

브라우저에서 수면 가이드 3개를 펼치고 다른 탭을 다녀온 후, 이전과 같은 1,712px 위치와 펼침 상태가 유지됐다. 새로고침 후에도 같은 위치를 확인했다. 검색에서는 원문을 읽은 후 해당 결과 카드가 보이는 목록 위치로 복원됐고, FAQ에서는 `기침` 검색어와 펼친 답변이 유지됐다. 3개월의 펼침 상태는 2개월과 분리됐다.

회귀 검사는 실제 Zustand 저장소를 별도의 메모리 세션 저장소로 실행한다. 화면/아기 분리, 재생성 시 복원, 캐시 정리, 잘못된 저장값·JSON·저장 차단 복구, 안전한 복귀 주소를 확인한다. 운영 DB 쓰기는 하지 않았다.

기존 Supabase 온라인 콘텐츠 연결 실패와 Next.js middleware 파일명 사용 중단 예정 경고는 별도 과제로 남아 있다. 실제 iOS/Android 키보드·스크린리더와 부모 대상 사용성 관찰은 STEP 7에서 진행해야 한다.
