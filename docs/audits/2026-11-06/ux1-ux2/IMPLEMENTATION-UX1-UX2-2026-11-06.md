# UX1·UX2 구현 — 공통 상단·월령 요약·건강 FAQ

작업일: 2026-11-06 · 저장소: `D:\workplace\03-INFANTPEDIA`

상태: **로컬 구현·Chrome QA·격리 배포 빌드·실제 3219 앱 반영 확인 완료**. 운영 배포와 의료 전문가 검수 완료를 뜻하지 않는다.

## 1. 반영한 변경

- 공통 페이지 헤더의 제목/간격을 정리했다. 월령 선택은 간결한 한 줄과 펼치는 0–12개월 선택으로 바꿨다.
- 백과의 주제 8개는 큰 아이콘 상자에서 텍스트 탭으로 바꿨다. 기본 화면에서는 2줄로 모두 보이고, 큰 글씨에서는 줄을 늘린다.
- 실제 월령과 둘러보는 월령의 차이, 신생아, 12개월 이후 참고 범위를 계속 표시한다. 14개월 아기를 ‘우리 아기 12개월’로 표시하지 않는다.
- 월령 요약은 확인한 원문의 두 문장을 먼저 보여주고 전체 원문과 수유·수면 참고 수치는 각각 펼쳐 보게 했다. 설명을 절차처럼 번호로 나열하지 않는다.
- 월령 요약의 일반 `food` 분류는 ‘수유·먹기’로 표시하고 검색의 분류명도 일치시켰다. 전용 이유식 주제는 유지한다.
- FAQ는 중복 제목과 큰 분류 그리드를 정리했다. 주제/결과 개수·긴급 필터를 간결하게 모았고, 질문과 기존 요약이 먼저 보인다.
- FAQ 기본 목록은 분류별 2개씩 보여준다. 모두 보기·주제 선택·검색으로 나머지 질문에 계속 접근할 수 있다. 이전에 열었던 질문은 기본 목록 범위 밖이어도 복원한다.
- 답변의 큰 색 상자를 줄이고 소제목·여백·굵기·의미별 색으로 구분했다. 핵심/조건은 진한 글씨, 행동은 청록, 주의는 주황, 긴급 도움은 붉은색으로 표시한다.
- 자료 대조와 전문가 검수를 공통 규칙으로 표시한다. 자료 링크나 대조일만으로 ‘전문가 검수 완료’를 표시하지 않는다. 이름/유효한 날짜가 없는 검수 메타데이터도 완료로 표시하지 않는다.
- 검색 상세에서도 같은 FAQ 본문을 사용한다. 긴급 안내·저월령 진료 안내·119 링크·전문 검수 대기 표시는 유지한다.

## 2. 원문과 읽기 상태 보호

### 표시용 요약/강조

의료·육아 원문이나 수치를 새로 작성하지 않았다. 월령 요약의 미리보기는 공개 스냅샷의 원문 문장에서 가져온 발췌다. FAQ 미리보기는 기존 구조화된 요약이 있는 경우 그 필드를 사용한다.

월령별 원문 13개와 정확히 일치할 때만 해당 미리보기를 적용한다. 원문이 바뀌면 이전 미리보기를 재사용하지 않고 새 원문 전체를 표시한다. 의료 문구의 강조도 기존 구조화 답변의 **완전한 문단 37개**를 기준으로 지정했다. 해당 문단이 바뀌면 예전 강조를 이어 붙이지 않는다.

글자·부정 표현·단위·문장부호를 바꾸지 않고 강조 부분만 구분한다. 원문을 HTML로 삽입하지 않는다. 새 요약이 없는 답변에는 자동 요약을 만들지 않았으며, 구조화되지 않은 긴급 답변은 접힌 상태에서도 기존 전문을 유지한다.

### 읽기/탐색

기존 아기·월령·주제별 읽기 저장소와 URL 구조를 유지한다. 요약/참고 수치 펼침, FAQ 검색어·주제·열린 답변을 돌아왔을 때 복원한다. ‘이유식’에서 ‘수유·먹기’로 바뀐 분류는 예전 저장 키와 읽기 앵커를 유지해 기존 펼침 상태를 잃지 않게 했다.

월령 선택과 FAQ 분류 선택은 키보드로 조작할 수 있고, 닫을 때 선택 버튼으로 초점을 돌려준다. 질문의 접근 가능한 이름과 검수 상태 설명도 구분했다.

## 3. 실제 길이와 위치

동일한 390×844px Chrome, 2개월, 합성 프로필, 기본 글자 크기, 처음 진입/기본 접힘 상태 기준이다. 실 사용자 행동 통계가 아니다.

| 항목 | 이전 | 최종 | 변화 |
| --- | ---: | ---: | --- |
| 월령 요약 제목 시작 | 529px | 256px | 273px 위로 |
| 건강 FAQ 첫 질문 카드 시작 | 1,372px | 642px | 730px 위로 |
| 월령 요약 페이지 전체 길이 | 1,579px | 1,171px | 약 26% 감소 |
| FAQ 페이지 전체 길이 | 3,150px | 2,179px | 약 31% 감소 |

FAQ 길이 감소에는 처음 보이는 질문을 9개에서 6개로 줄인 효과도 포함된다. 모든 질문에 접근하는 경로는 유지했다. 월령 페이지는 전체 원문/참고 수치를 펼쳤을 때 길이가 다시 늘어난다.

중간 구현에서는 첫 질문이 하단 고정 메뉴와 겹치는 문제가 발견되어 수정했다. 최종 추가 검사에서 하단 안전 영역을 34px로 모의했을 때 질문 제목 끝은 711px, 메뉴 시작은 724px였다. 이는 Chrome의 CSS 모의 검사이며 실제 iOS/PWA 검증을 대신하지 않는다.

## 4. 검증

- 타입 검사: `npx tsc --noEmit` 통과
- 린트: 저장소의 ESLint 설정으로 최종 `src` 전체 통과
- 배포 빌드: `npm run build -- --webpack` 통과. 사용자용 앱을 방해하지 않도록 동일 소스의 격리 QA 폴더에서 실행했다.
- 회귀 시나리오 **73개**: 표시/원문 보호 11 + 새 UI 브라우저 18 + 기존 콘텐츠 안전성 17 + 읽기/탐색 10 + 기존 콘텐츠 화면 9 + 일과 목록 8
- 월령 13개 원문, FAQ 전체 89개 ID 접근, 구조화 답변 18개의 모든 본문 필드 보존 확인
- 320/360/390/430px, 밝은/어두운 모드, 200% 루트 글자 확대, 키보드, 빈 검색, 오프라인/재시도, 변경된 공개 원문의 안전한 표시 확인
- 8개 백과 주제와 5개 주요 메뉴, 설정 5개 항목의 이동·가로 넘침 확인
- 실제 3219 앱에서 공개 콘텐츠 GET 2건과 요약 표시 확인. 추가로 fixture를 연결해 원문 펼침·FAQ 조건 강조 확인. 해당 테스트의 런타임 오류와 변경 API 시도는 0개였다.
- 검증한 QA 소스와 실제 반영한 UI 소스 18개 파일의 해시 일치 확인
