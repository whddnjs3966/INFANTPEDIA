# 베이비빌리 벤치마킹 · INFANTPEDIA 리디자인 계획

작성: 2026-11-06

목표: 초록색 중심의 무거운 인상을 걷어내고, 밝은 색과 친근한 이미지 속에서 필요한 내용을 빠르게 찾고 기록하는 앱으로 정리한다. 기존의 ‘요약 먼저, 상세는 선택 후’와 최근 요청한 작은 글자 크기를 유지한다.

**현재 반영:** 전문가 검수 기능·대기/완료 표시·검수자/검수일·상태 판정 제거. 참고 자료·의료진 상담 안내·긴급 도움은 보존.

**2026-11-07 읽기 개선:** 새 그림 8종과 백과 8개 카테고리의 목록/펼침 구조를 반영했다. [최신 결과](../../2026-11-07/encyclopedia-reading/IMPLEMENTATION-ENCYCLOPEDIA-READING-2026-11-07.md). 24개 화면/322개 패널·원문 필드3,893개·64개 확대/다크 조합을 확인했다. 다음은4단계 잔여 흐름이며 전체 의료 검증 완료는 아니다.

**2026-11-07 추가 반영:** 홈의 그림·색감을 주요 나머지 탭에 확장하고 설정/기록/아기 선택/접종 입력의 큰 글씨 재배치를 확인했다. [최신 결과](../../2026-11-07/illustrated-tabs/IMPLEMENTATION-ILLUSTRATED-TABS-2026-11-07.md). 당시 남았던 3단계는 위 읽기 개선에서 반영했고 4단계 잔여 흐름은 남아 있다.

**진행 갱신:** 1단계 공통 디자인과 2단계 홈 구현을 완료했다. 밝은/어두운 공통 테마·자체 SVG·홈 프로필/추천/빠른 기록을 실제 로컬 앱에 반영했다. [구현·검증 결과](../bright-home/IMPLEMENTATION-BRIGHT-HOME-2026-11-06.md). 4~7단계는 아래 계획으로 남아 있으며, 다른 탭의 공통 색상 적용을 전체 개편 완료로 보지 않는다.

## 1. 무엇을 직접 확인했는가

확인 자료는 베이비빌리 공식 사이트와 공식 스토어의 공개 소개/홍보 화면이다. 네이티브 앱 로그인이나 실제 기록 입력은 수행하지 않았다. 아래의 픽셀·색상 코드·동작 시간은 INFANTPEDIA 제안값이며 베이비빌리의 내부 디자인 수치라고 주장하지 않는다.

| 직접 확인한 요소 | 참고한 이유 | INFANTPEDIA에 적용할 방향 |
|---|---|---|
| 공식 웹의 밝은 파랑과 살구색 영역, 부드러운 입체 캐릭터 | 텍스트만 있는 도구보다 친근한 첫인상을 만든다 | 밝은 하늘색/살구색과 자체 구름 캐릭터를 소규모로 사용 |
| 이미지와 시기별 안내를 함께 보여주는 소개/홈 예시 | 아기의 현재 시기와 콘텐츠의 연결을 눈으로 인식 | 실제 월령과 둘러보는 월령을 구분하고 대표 안내 1개 배치 |
| 콘텐츠·사진 게시물·건강 기록을 목적별로 묶은 공개 화면 | 한 화면에서 모든 문장을 읽지 않아도 찾을 수 있다 | 주제 이미지 + 상황 제목 + 한 줄 요약 → 상세 |
| 같은 시기 부모 커뮤니티와 가족 기록/다운로드 기능 소개 | ‘다시 방문할 이유’와 ‘함께 기록’에 초점 | 먼저 이어 읽기·저장한 글·성장 기록의 재접근을 개선 |

출처: [베이비빌리 공식 소개](https://babybilly.app/ko), [Google Play 공식 앱 소개·스크린샷](https://play.google.com/store/apps/details?hl=ko&id=kr.villagebaby.billyapplication), [운영사 서비스 소개](https://villagebaby.kr/). 확인일 2026-11-06.

공개 웹에서는 파란 메인 영역과 살구색 배경, 캐릭터·모바일 화면 예시를 직접 관찰했다. 정적인 공개 화면만으로 네이티브 앱의 애니메이션 시간·전체 클릭 흐름을 검증하지 않았다. 애니메이션은 아래 제안과 실제 구현 QA로 확정한다.

## 2. 새 색감 — 하늘색 + 살구색 + 화이트

추천안은 **넓은 흰 바탕, 옅은 하늘색/살구색 카드, 또렷한 파란 버튼**이다. 짙은 단색의 큰 프로필 상자는 밝은 이미지/프로필 영역으로 전환한다. 한 화면의 넓은 색 영역은 대표 카드 1곳에 집중한다.

| 용도 | 제안색 | 적용 |
|---|---|---|
| 앱 바탕 | `#FAFBFF` | 거의 흰 바탕으로 가벼운 인상 |
| 기본 카드 | `#FFFFFF` | 설명/기록/설정의 안정적인 표면 |
| 기본 버튼·선택 | `#2666B8` | 흰 글자 버튼, 선택한 탭, 주요 링크 |
| 하늘색 면 | `#EAF4FF` | 수면/월령 안내·선택 배경 |
| 살구색 면 | `#FFF0E5` | 홈 대표 안내·부드러운 이미지 배경 |
| 라벤더 면 | `#EEEBFC` | 놀이/발달 커버의 보조색 |
| 본문 | `#34323C` | 제목과 주요 내용 |
| 보조 문구 | `#716D7C` | 출처·시간·맥락 |
| 경계 | `#EDF0F7` | 얇은 구분선, 필요한 카드 경계 |

주의/긴급은 기존 의미별 색과 텍스트 라벨을 유지한다. 파란색은 선택/행동, 주황/붉은색은 주의/긴급이라는 역할을 섞지 않는다. 그래프는 범례·선 모양·단위를 함께 제공한다.

다크 모드는 같은 색을 단순 반전하지 않고 바탕 `#1D2130`, 카드 `#282E40`, 본문 `#F5F7FF`, 선택 `#A6CEFF`, 살구 보조 `#F5C7AB`를 출발점으로 검증한다. 최종 값은 모든 카드/필터의 실제 대비 검사 후 확정한다.

완료 기준: 새 토큰뿐 아니라 하드코딩된 `teal-*`/초록 아이콘·테두리·차트·링크까지 목록화해 전환한다. 기본 글자/버튼 대비, 다크 모드의 명도 위계, 긴급 안내의 식별을 확인한다.

## 3. 이미지와 일러스트

자체 구름 친구와 둥근 소품을 사용한다. 홈 구현에서 시안과 별도로 정돈한 SVG 7종을 추가했고 구름/수면/먹기/기록을 배치했다. 외부 이미지 다운로드 없이 표시된다. 아래 전체 탭의 커버·빈 상태 확대는 후속 단계다.

| 이미지 묶음 | 수량/형태 | 배치 |
|---|---|---|
| 대표 캐릭터 | 기본 1개 + 인사/휴식/기록 등 소수 포즈 | 홈 대표 안내, 첫 기록, 완료 피드백 |
| 주제 커버 | 수면·먹기·놀이·건강·기록·외출 6종 | 백과/꿀팁의 짧은 카드 |
| 빈 상태 | 기록 없음·검색 결과 없음·연결 문제 3종 | 해당 문제와 다음 행동 바로 위 |
| 아기 사진 | 현재의 선택/변경 기능 유지 | 프로필; 사진이 없으면 기본 일러스트 |

- 실사 이미지가 필요한 경우에는 실제 동작/준비물을 이해시키는 곳에 사용한다. 모든 카드에 임의의 아기 사진을 반복하지 않는다.
- 카드 커버는 같은 비율·크롭·배경/그림자 규칙을 적용한다. 단순 주제 이미지는 벡터, 입체 그림은 적절한 크기의 WebP/AVIF를 검토한다.
- 캐릭터 그림을 아기의 실제 발달 상태나 정상/비정상 판단으로 사용하지 않는다.
- 첫 화면 대표 이미지 1개 외 이미지는 필요 시 불러오고, 이미지 영역을 미리 확보해 화면이 튀지 않게 한다. 실패 시 제목/행동이 그대로 남는다.

완료 기준: 이미지를 제거하거나 로딩에 실패해도 정보 탐색/기록을 진행할 수 있다. 의미 있는 이미지의 대체 텍스트와 장식 이미지의 접근성 처리를 구분한다.

## 4. 폰트·문장·강조

최근 요청한 크기를 기본으로 유지한다. 베이비빌리의 공개 홍보 문구가 크다는 이유로 앱 본문까지 키우지 않는다.

| 위계 | 크기/굵기 제안 | 규칙 |
|---|---|---|
| 화면 제목 | 22px / 600–700 | 한 화면의 주목점 1개 |
| 프로필 이름 | 20px / 600 | 긴 이름 줄바꿈·아기 전환 유지 |
| 섹션 제목 | 18px / 600–700 | 주제를 분리 |
| 카드 제목 | 15–16px / 600 | 실제 상황을 제목으로 표현 |
| 본문 | 15px / 400 | 24–28px 행간, 짧은 문단 |
| 시간·맥락·자료 | 13px / 400–500 | 충분한 대비, 핵심 행동을 작은 글씨에 넣지 않음 |
| 입력칸 | 최소 16px | 수치·날짜·기록의 입력 가독성 유지 |

기존 글꼴 계열을 유지하고 굵기를 정리한다. 아기자기한 손글씨체는 본문에 사용하지 않는다. 숫자는 단위/범위와 붙여 읽고, 조건·부정·도움 요청 문장을 잘라내지 않는다. 전문 검수 상태나 대기 배지는 추가하지 않는다. 참고 자료는 상세에서 열 수 있다.

## 5. 탭별 배치 변경

### 홈

1. 가벼운 아기 프로필 행: 사진·이름·실제 월령·전환·검색.
2. **대표 안내 1개:** 옅은 살구색, 작은 그림, 해당 월령에 유효한 상황별 요령.
3. 성장 기록/건강 질문 빠른 행동 2개. 기존 입력·검색으로 연결.
4. 이 시기에 궁금한 글 2개를 이미지가 있는 짧은 카드로 표시.
5. 최근 기록/접종 일정은 실제 데이터가 있는 상태와 없는 상태를 구분해 표시.

대표 안내가 수유/수면을 임의로 단정하거나 월령별 과제를 강요하지 않도록 현재의 적용 월령/원문 보호를 유지한다.

### 백과

- 월령 선택은 간결하게, 8개 주제는 빠르게 전환할 수 있게 유지한다.
- 큰 정보 상자 대신 주제 커버·상황 제목·핵심 1–2줄을 보여준다.
- 월령 요약은 이미지/요약/상세, 건강 FAQ는 질문/중요 조건/답변 상세/참고 자료로 구성한다.
- 긴급 안내는 접힘이나 추천 캐러셀 안에 넣지 않는다.

### 기록

- 실제 최근 수치와 측정일 → 변화 그래프 → 기록 목록 순서.
- ‘추가’ 동작을 찾기 쉽게 두고, 날짜·단위를 이미지보다 우선한다.
- 접종은 이번 시기/기록 여부가 먼저 보이게 정리한다. 그림은 빈 상태나 기록 완료에 제한한다.

### 꿀팁

- 현재 상황별 실용 팁 30종을 이미지 커버와 묶고, 주제별로 짧게 탐색한다.
- 시간대 목록은 남기되 전체 그래프·상세 방법은 선택해서 연다.
- 같은 팁이 상단/주제/일반 팁에 연달아 중복되지 않도록 추천 순서를 조정한다.
- 식단은 메뉴 조합/질감·준비 주의/참고 자료를 나누고, 숫자가 목표처럼 보이지 않게 한다.

### 설정·검색

- 설정은 기존 5개 탭과 실제 선택 상태를 유지하고, 표면/아이콘/입력 규칙을 새 색으로 통일한다.
- 검색은 직접 검색 → 현재 월령/전체 범위 → 결과 목록 → 상세의 흐름을 유지한다.
- 모든 결과에 이미지를 강제하지 않고 주제·제목·월령으로 식별한다. 이전 조건과 읽던 위치를 복원한다.

## 6. 애니메이션

| 상황 | 제안 | 제한 |
|---|---|---|
| 버튼/필터 선택 | 120–160ms 색·배경 전환 | 터치/키보드 동작 즉시 처리 |
| 카드 펼침 | 180–220ms 높이/불투명도 | 내용 전체 접근·포커스·읽기 위치 유지 |
| 아기 선택 시트 | 현재 흐름을 정돈한 짧은 전환 | 선택/닫기/포커스 복귀 유지 |
| 캐릭터 | 진입 시 한 번, 약 1초의 작은 인사 | 반복 진동/자동 영상/지속 깜빡임 없음 |
| 기록 완료 | 짧은 체크/색 변화 | 저장 결과 텍스트도 함께 제공 |

모션 감소 환경에서는 즉시 전환하거나 정적으로 표시한다. 화면 전환마다 전체 콘텐츠가 순서대로 느리게 나타나지 않게 한다. 수치·의료 안내·긴급 행동에는 장식 모션을 넣지 않는다.

| 성장 순간/기록 카드 | 기존 성장·접종·사진과 연결 | 2차. 사실인 기록만 카드에 표시하고 이미지 내보내기는 별도 구현 |
| 가족과 함께 기록 | 기존 공유/백업 기능과 연결 | 실제 운영/권한/충돌 확인 후 적용. 공개 소개만 보고 동작 완료로 간주하지 않음 |
| 같은 시기 커뮤니티·쇼핑 | 별도의 서비스 운영/개인정보·콘텐츠 관리 필요 | 후속 확장 후보. 이번 0–12개월 정보·기록 리디자인의 선행 조건으로 두지 않음 |

자료의 정확성은 기존 공식 출처 대조·수치 정합성·회귀 검사로 계속 확인한다. 전문가 계정/배정/승인/검수 상태 기능은 개발 목록에서 제외한다.

## 9. QA와 판단 기준

- 320/360/390/430px, 밝은/어두운 모드, 200% 글자 확대. 가로 넘침·잘린 버튼·하단 메뉴 겹침 없음.
- 아기 이름이 길거나 복수 아기/사진 없음/0개월/12개월 초과/기록 없음/오프라인인 상태를 각각 확인한다.
- 기본 조작 영역 44px 이상, 키보드/포커스 복귀, 스크린리더 제목/이미지 설명과 실제 모바일 기기 확인.
- 주요 콘텐츠를 세 번 이내의 선택으로 찾고, 홈에서 기존 성장 입력까지 두 번 이내로 진입하는 것을 목표로 실제 경로를 측정한다.
- 전후 스크롤 길이만 비교하지 않고 제목 이해·정보 찾기·기록 완료의 성공 여부를 함께 비교한다.
- 이미지가 없어도 기능 완료 가능. 첫 화면 이미지 크기 예산을 정하고 초기 표시·스크롤·화면 이동의 지연을 이전 화면과 비교한다.
- FAQ 원문/응급 안내/수치·단위, 저장된 성장·접종 기록, 로그인·백업의 실제 상태를 변경 전후 비교한다.
- 출처가 전문가 승인이나 정확성 보증 배지로 바뀌지 않았는지 확인한다.

최종 구현에서는 그림·색감·모션을 한 번에 전 탭에 흩어 넣기보다 **색상/이미지 기준 → 홈 → 정보 탭 → 기록/보조 화면 → 모션/기능 → 전체 QA** 순서로 진행한다.
