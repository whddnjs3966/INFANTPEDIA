# INFANTPEDIA 전체 UI/UX 단순화 계획

작성: 2026-11-05 · 실행 현황 갱신: 2026-11-06

**UX1·UX2 로컬 구현/QA 완료, UX3–UX7 대기.** [구현 결과와 다음 작업](../../2026-11-06/ux1-ux2/IMPLEMENTATION-UX1-UX2-2026-11-06.md). 아래 내용은 전체 전환 계획이며, 자료 대조·실기기·운영 배포 완료와 구분한다.

## 1. 결정할 방향

**‘제목 → 핵심 한 줄 → 필요한 숫자/핵심 포인트 → 눌러서 상세’로 통일한다.**

크림색 배경과 진한 청록색을 중심으로, 흰색 면·명확한 글자·여백으로 정보를 구분한다. 홈·백과·기록·꿀팁·설정의 하단 5개 탭은 유지한다. 모든 카드를 같은 크기로 만들기보다, 요약 카드 / 간결한 목록 / 상세 본문의 세 가지 역할을 구분한다.

핵심 내용은 ‘작게 줄이기’보다 **한 번에 보여주는 양과 중복된 제목·조작부를 줄이는 방식**으로 단순화한다. 긴급 행동·대상 조건·삭제 범위·백업 실제 상태는 처음부터 보이게 한다.

권장안은 **요약 카드 중심**이다. 밀도가 높은 사용자를 위한 비교안은 **제목·핵심 문구를 앞세운 목록 중심**이다. 두 안 모두 상세를 열 수 있고, 참고 자료를 상세에서 볼 수 있게 한다.

## 2. 이번에 확인한 범위와 근거

- 주요 5개 탭, 백과의 8개 주제, 설정의 5개 항목, 기록의 성장/접종, 꿀팁 2/6개월, 검색/질문 상세, 원더윅스·개인정보·로그인·첫 시작: **24개 화면 상태** 확인.
- 기본 상태와 주요 아코디언을 펼친 상태를 캡처했다. 390×844px Chrome, 합성 아기 2명·합성 측정 기록 2개·공개 콘텐츠 스냅샷 사용.
- 주요 컴포넌트·설정/백업의 조건부 UI·관리자 소스를 함께 읽었다. 로그인 후 실계정·서버 연결·백업 충돌·삭제 실행은 화면 실증 범위에 포함하지 않았다.
- 제품의 기능·정보 묶음별 **83개 검토 단위**: [CARD-BY-CARD-UI-AUDIT.md](CARD-BY-CARD-UI-AUDIT.md). 점검표의 한 행은 카드/목록/안내 블록 단위다. FAQ 89개 각각의 자료 대조 완료를 뜻하지 않는다.
- 원시 측정: [all-tabs-audit.json](evidence/all-tabs-audit.json), 검색 조건을 보완한 측정: [search-refined.json](evidence/search-refined.json).
- 화면 예시의 주제 전환·원문/답변 펼치기와 320/390/736px·밝은/어두운 모드를 확인했다. 이는 제품 리디자인의 회귀 검사와 구분한다. [예시 확인 결과](evidence/prototype-qa.json), [자료 설명](evidence/README.md).

### 공통 상단

- 페이지 제목·검색은 한 줄의 작은 헤더로 정리한다. 같은 주제 제목과 월령 배지를 반복하지 않는다.
- 월령 선택은 `‹  2개월 · 우리 아기  ▾  ›` 형태의 56–64px 정도 한 줄 컨트롤로 축소한다. 눌렀을 때 기존 0–12개월 선택을 제공한다. 실제 월령과 둘러보는 월령이 다르면 차이를 텍스트로 표시한다.
- 백과 주제 8개는 2줄의 텍스트 탭으로 전부 노출하는 안을 우선 적용한다. 기존 큰 아이콘 타일을 줄여 선택 동작 수를 늘리지 않는다. 큰 글자에서는 자연스럽게 줄을 늘린다.
- 홈·기록의 아기 선택 디자인은 공유한다. 선택한 아기와 둘러보는 월령을 혼동하지 않게 구분한다.
- 읽기 위치·선택 월령·필터·펼침 상태를 보존한다. 설정 탭 전환은 사용자가 요청한 상단 유지 동작을 계속 사용한다.

## 5. 카드와 상세 표시 규칙

### 첫 화면의 카드

1. 제목: 16–18px, 600–700 굵기, 일반적으로 1–2줄.
2. 핵심 설명: 16px, 1–2문장 또는 핵심 포인트 2–3개.
3. 메타 정보: 14px. 월령·실제 날짜·자료 상태 중 해당 카드에 필요한 것만 표시.
4. 동작: 펼치는 카드는 아래 화살표와 ‘자세히’, 다른 화면으로 가는 항목은 오른쪽 화살표와 목적지를 표시. 한 카드에 주된 동작 하나.
5. 큰 카드 안에 여러 개의 테두리 카드·색 상자를 계속 중첩하지 않는다. 같은 성격의 항목은 한 면 안의 행과 구분선으로 묶는다.

### 상세를 여는 방식

- 짧은 안내: 같은 위치에서 펼치기. 기본적으로 같은 묶음 안의 하나를 열되 체크/입력 상태를 잃지 않는다.
- 긴 가이드: 제목 목록 → 해당 글 상세 화면. 뒤로 가면 같은 월령·필터·목록 위치로 돌아온다. 아코디언을 세 겹 이상 중첩하지 않는다.
- 기록 입력/편집: 기존 입력 기능을 유지한 시트/대화상자. 저장·취소와 현재 아기를 명확하게 표시한다.
- 수치 참고와 출처: 요약에 참고 범위를 보이고 상세의 자료를 펼친다.
- 위험 안내: 긴급 행동, 대상 월령, 금기, 삭제 대상·되돌릴 수 없음, 실제 저장 위치는 접힌 상태에서도 읽을 수 있게 한다.

## 6. 글을 나열한 카드의 강조 규칙

**단어를 많이 칠하기보다 ‘사용자가 기억하거나 행동할 한 덩어리’를 강조한다.**

| 의미 | 표시 | 예시/조건 |
| --- | --- | --- |
| 핵심 개념 | 진한 본문색 + 굵기 700 | 월령 요약의 ‘목 가누기’, ‘시선 이동’, ‘옹알이’ |
| 해야 할 행동 | 진한 청록 + 굵기 700, 필요 시 ‘이렇게’ 라벨 | 확인·기록·상담 등 원문에서 지정한 행동 문구 |
| 대상/예외/부정 | 같은 문장 안에서 굵게, 의미 단위 전체 보존 | ‘생후 3개월 미만’, ‘의심되면’, ‘기다리지 마세요’ |
| 주의/금기 | 진한 호박색 + ‘주의’/‘피해주세요’ + 아이콘 | 제품 농도·준비 조건·피해야 할 행동 |
| 긴급 도움 | 진한 장미색 + ‘바로 도움 요청’ 라벨 | 기존 구조화한 위험 신호와 도움 행동. 키워드로 새 긴급도를 판정하지 않음 |
| 숫자·단위 | 굵은 중립색 + 단위·범위·기준 함께 | `120–150mL`만 떼어 정상/목표처럼 크게 만들지 않음 |
| 검색어 | 옅은 배경 표시 + 진한 글씨 | 검색 일치 표시와 의료적 중요도 표시를 구분 |
| 참고 자료 | 중립색 작은 텍스트와 링크 | 원문 링크·자료 확인일을 제공 |

- 한 문단에서 강조 1–2군데, 요약 카드 전체에서 우선 2–3개를 선택한다. 문맥 보존이 필요한 조건·금기는 이 제한보다 우선한다.
- 본문 도중 글자 크기를 들쭉날쭉하게 바꾸지 않는다. 문단은 16px를 유지하고 굵기·색·라벨로 구분한다. 중요한 행동은 별도 짧은 문장으로 분리할 수 있다.
- ‘먹이세요’와 ‘먹이지 마세요’, ‘기다리세요’와 ‘기다리지 마세요’에서 부정 표현을 강조 밖으로 떨어뜨리지 않는다. 월령·측정 부위·시간·상태 같은 조건을 생략하지 않는다.
- 수유·수면 등 참고 수치는 목표 달성을 암시하는 녹색 체크, 달성률, 좋음/나쁨 배지로 표시하지 않는다.
- 중요도를 색 하나로만 표시하지 않는다. 굵기·라벨·아이콘을 함께 쓴다. [W3C 색상 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

### 월령 요약 예시

현재는 세 문장을 전부 번호로 보여준다. 변경안은 기존 원문에서 고른 핵심 변화 2–3개를 먼저 보여주고, **목 가누기 / 시선 이동 / 옹알이·표정** 등의 핵심 개념만 강조한다. ‘원문 자세히’에서 전체 문장과 참고 수치를 확인한다. 이는 월령별 공통 설명이며 이 아기의 실제 관찰 결과가 아님을 함께 표시한다.

### 건강 FAQ 예시

접힌 상태: **질문 → 핵심 답변 한 문장 → 대상·참고 자료**. 핵심 행동이 긴급하면 질문을 열기 전에도 대상 조건과 행동을 표시한다.

펼친 상태: **핵심 답 → 지금 할 일 → 피할 일 → 진료·도움 → 근거**. 모두 큰 색 상자로 나누기보다 짧은 소제목·여백·아이콘으로 읽는 순서를 만든다. 원래 FAQ에 없는 행동 요약을 자동으로 만들어 붙이지 않는다.

예를 들어 기존 `fever_05`의 ‘생후 3개월 미만에서 발열이 있거나 의심되면 바로 의료진에게 연락해 진료를 받으세요. 해열제 반응을 기다리며 진료를 미루지 마세요.’는 **대상 조건과 기다리지 말라는 표현을 같은 문맥**에 둔다. 체온 숫자만 크게 떼어 강조하지 않는다. 이 예시는 기존 문장의 표시 계획이며 기존 본문의 조건과 행동을 유지한다.

### 구현 때 지킬 내용 모델

- 현재 `FormattedContent`의 숫자/주의 단어 정규식은 중요도를 해석하지 못한다. FAQ의 `HealthCareAnswer`는 이 컴포넌트를 사용하지도 않는다. 두 경로와 검색 상세를 함께 정리해야 한다.
- 우선 기존 `care.summary / steps / avoid / seekHelp`, `urgency`, `evidence`를 사용한다. 나머지 텍스트는 확인한 핵심 문구와 그 의미를 **콘텐츠 ID·원문 버전별로 명시**한다.
- 강조 지정은 해당 원문과 정확히 일치할 때 적용한다. 원문이 바뀌면 예전 강조/요약을 임의로 재사용하지 않고 원문과 확인 중 상태로 되돌린다.
- 단순 설명을 마침표마다 무조건 절차로 변환하지 않는다. 설명 문단·핵심 포인트·실제 단계 목록을 구분한다.
- 강조를 제거한 텍스트와 검색 상세의 내용은 같은 원문을 유지한다. 월령·금기·단위·부정 표현·출처가 요약 과정에서 누락되지 않도록 확인한다.

흰색·크림·중립 글자가 화면의 대부분을 차지하도록 한다. 청록색은 선택과 행동에, 주의/긴급색은 해당 의미에만 사용한다. 보라·핑크·파랑을 모든 제목 아이콘의 장식색으로 반복하지 않는다. 그래프 활동 구분색은 의미가 있는 범례와 함께 유지한다. 로그인 제공자의 고유 브랜드색도 구분을 위해 유지할 수 있다.

### 글자와 간격

- Noto Sans KR 한 계열. 페이지 제목 24–28px, 구역 제목 18–20px, 카드 제목 16–18px, 본문 16px, 보조 14px. 핵심 숫자는 실제 기록일 때 24–28px까지 사용.
- 본문 줄높이 1.65–1.8, 일반 굵기 400–500, 중요한 문구/제목 600–700. 전 문장을 굵게 만들지 않는다.
- 카드 안쪽 16px, 구역 간 20–24px, 목록 행 최소 64px를 시작점으로 검토한다. 본문 안에 또 여러 겹 20px 여백을 넣지 않는다.
- 모서리 16–20px 중심, 그림자는 한 가지 미세한 단계. 이미 둥근 면에 강한 테두리·그림자·색 배경을 모두 겹치지 않는다.
- 누르기 영역은 일반적으로 44–48px 이상을 설계 목표로 한다. WCAG 2.2 AA의 대상 크기 기준은 예외를 포함한 24×24 CSS px이며, 앱의 편의 목표와 구분한다. [W3C 대상 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 일반 글자 대비 4.5:1, 큰 글자 3:1을 확인하고 확대 200%에서 내용·기능을 보존한다. 16/14px는 이 앱의 설계 기준이며 WCAG가 지정한 최소 폰트 크기라는 의미는 아니다. [대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [글자 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)
