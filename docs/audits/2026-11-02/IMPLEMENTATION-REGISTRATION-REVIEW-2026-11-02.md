# 등록 대기 기록 비교·명시적 백업 갱신

작성: 2026-11-02 (Asia/Seoul)

## 완료 범위

검증 환경의 설정 → 가족에서 대기 중인 등록에 '기기·서버 기록 비교'를 추가했다. 기존 요청 ID·아기 ID·최초 payload로 등록 결과부터 확인하므로, 등록 대기 중 기기 기록이 달라져도 아기를 새로 만들지 않는다. 비교 단계는 현재 기기 내용을 서버에 덮어쓰지 않는다. 최초 요청이 아직 처리되지 않았던 경우에는 그 원본 요청으로 최초 등록을 완료할 수 있음을 버튼 아래에 안내한다.

- 프로필 값, 성장 기록의 ID·날짜·수치, 접종 항목·차수·날짜를 비교한다. 건수가 같아도 값이 다르면 표시한다. 기기/서버에만 있는 항목은 '기록 없음'으로 표시한다.
- 사용자가 확인한 경우에만 '기기 기록으로 백업 갱신'을 실행한다. 서버에만 있는 항목이 빠지는 전체 교체임을 명시하며, 취소하면 갱신하지 않는다. 자동 병합·서버 기록의 기기 덮어쓰기는 하지 않는다.
- 적용 직전 서버 버전과 내용을 다시 읽고 비교 당시와 일치하는지 확인한다. 계정·선택 아기·로컬 기록·이전 공유 연결이 바뀌어도 중단한다. DB 쓰기 자체는 기존 원자적 버전 검사를 사용한다.
- 갱신 request ID·기준 버전·내용을 먼저 영속 저장한다. 응답이 불확실하고 서버가 바뀌지 않았다면 같은 요청으로 재시도한다. 이미 반영된 결과를 재비교로 확인하면 서버에 다시 쓰지 않고 현재 버전으로 연결한다.
- 연결 정보 저장 실패 시 대기 요청·갱신 요청을 복구한다. 연결 성공 시 해당 계정/아기의 대기 요청만 정리하며 다른 아기의 상태와 로컬 프로필·성장·접종·사진·메모는 보존한다.

- 등록·비교 흐름 25개: 기존 13개에 비교·동일 건수 값 차이·명시적 반영·버전/기기/계정 변경·불확실한 응답·저장 실패 복구 등 12개 추가.
- 기존 원자적 DB 22개, 클라이언트 10개, 공유 중지 10개 회귀 통과. 이번 실행 합계 67개.
- 전체 ESLint, TypeScript, webpack 프로덕션 빌드 통과.
- 격리 QA 사본·가짜 로그인·로컬 모의 서버로 390px 차이 비교/취소/갱신, 갱신은 처리됐지만 응답이 503인 상황의 새로고침 복구, 로컬 저장값 보존, 실제 읽은 버전 3 연결, 360px 다크 모드 가로 넘침 없음 확인. pageerror 0건, 운영 DB 요청 0건. 화면을 직접 검토했다.
- 화면: registration-review-screenshots/. QA 개발 서버는 종료했다.

## 공개 상태와 한계

새 등록 기능은 NEXT_PUBLIC_ATOMIC_REGISTRATION_ENABLED=true인 검증 환경에서만 제공한다. 실제 환경 파일과 운영 DB·권한·스키마는 변경하지 않았다. 레거시 공유와 자동 백업 중지는 유지한다. 커밋·푸시·배포하지 않았다.

이번 비교는 '대기 중인 최초 등록'의 해결이다. 기존 서버 아기 선택·복원, 항목별 병합, 자동 백업 충돌 해결, 계정/아기 삭제·연결 해제 전체 구현을 완료한 것은 아니다. 서버와 기기의 차이를 유지한 채 자동 백업만 켜는 선택지는 제공하지 않는다. 실제 JWT·다중 DB 세션 검증도 남아 있다.
