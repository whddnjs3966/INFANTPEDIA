# 새 연결의 원자적 자동 백업·충돌·재시도

작성: 2026-11-02 (Asia/Seoul)

## 완료한 동작

- 최초 등록만으로 자동 전송하지 않는다. 검증 환경에서 사용자가 아기별 '자동 백업 켜기'를 선택해야 한다. 끄기 상태도 새로고침 후 유지하며, 이미 전송한 요청은 서버에서 완료될 수 있음을 안내한다.
- 선택한 아기의 변경을 3초 기다려 직렬 전송한다. 수락한 계정·아기·서버 버전이 기준이며 최신 버전을 임의로 가져와 덮어쓰지 않는다. 이전 REST delete→insert 경로는 호출하지 않는다.
- 요청 ID·기준 버전·원본 payload를 전송 전에 영속 저장하고 읽어 검증한다. 불확실한 응답 뒤에는 동일 요청으로 재시도한다. 그 사이 생긴 새 로컬 변경은 기존 요청에 섞지 않고 확인 후 다음 버전으로 전송한다.
- 서버 확인된 스냅샷과 버전을 함께 보관한다. 기기 저장 실패 시 이전 기준과 대기 요청을 복구한다. 계정/아기/연결이 바뀌거나 백업을 끈 뒤 도착한 응답은 기준 데이터에 반영하지 않는다.
- 변경이 없으면 서버 기록과 수락한 버전을 읽어 확인한다. 다른 버전이 있으면 충돌로 멈추며, 충돌 상태는 새로고침 뒤에도 유지한다. 기기 기록을 바꾸거나 자동 재전송하지 않는다.
- 가족/데이터 화면에서 대기·확인·전송·실패·현재 기록 확인·충돌 상태와 같은 요청 재시도를 표시한다. 새 변경을 이전 성공 상태로 표시하지 않는다. 성공 표시는 런타임에만 유지한다.
- 기존 등록 대기 비교를 연결된 아기의 충돌 비교에도 확장했다. 최신 서버와 비교 후 사용자가 명시적으로 선택하면 기기 내용으로 서버 백업을 원자적으로 갱신하고 대기 요청/충돌을 정리한다. 다른 아기의 기록과 기기 사진·메모·발달 관찰은 유지한다.

## 계정 고정 SQL

`sql/009_account_bound_backup.sql`은 예상 로그인 계정을 서버 auth.uid()와 대조한 뒤 기존 원자적 쓰기를 호출한다. 두 계정 모두 편집 권한이 있어도 요청 도중 다른 계정으로 바뀌면 거부한다. 클라이언트가 소유자를 정하는 기능이 아니다. 일반 REST 표 권한을 다시 열지 않는다.

007 이후 적용하는 검증 환경용 SQL이며 운영에는 실행하지 않았다. 신규 등록까지 검증하려면 007 → 008 → 009를 준비한다. 최신 비교 UI의 쓰기도 009 경로를 사용한다. RPC가 없으면 실패 안내하며 레거시 방식으로 회귀하지 않는다.

## 기능 공개 상태

실제 환경 파일은 변경하지 않았다. 새 등록은 NEXT_PUBLIC_ATOMIC_REGISTRATION_ENABLED=true, 자동 백업은 여기에 NEXT_PUBLIC_ATOMIC_AUTOBACKUP_ENABLED=true까지 지정한 검증 환경에서만 제공한다. 아기별 명시적 켜기도 별도로 필요하다. 운영 클라우드·레거시 공유 중지는 유지한다.

## 남은 작업

1. 기존 서버 아기 목록·새 기기 복원·서버 내용을 기기로 수락하는 복원, 항목별 병합 UX. 현재 비교의 선택은 기기→서버 명시적 갱신이며 자동 병합은 아니다.
2. 새 연결 해제·아기 삭제·계정 파기·가족 초대/권한 철회 경로의 전체 전환.
3. 실제 JWT·다중 DB 세션 및 실기기/다중 탭 충돌 검사. 단일 프로세스 모의 저장소와 PGlite 검증으로 실서비스 동시성을 완료 판정하지 않는다.
4. 생성/조회/복원/관리자/삭제 전체 경로 전환 후 검증된 기능만 최소 권한으로 공개. 비활성 레거시 소스 제거도 남아 있다.
