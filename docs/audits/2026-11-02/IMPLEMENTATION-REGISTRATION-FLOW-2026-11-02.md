# 새 온라인 등록과 기기 기록 연결 흐름

작성: 2026-11-02 (Asia/Seoul)

## 구현

설정 → 가족에 신규 온라인 등록 확인창을 연결했다. 기존 로컬 아기 등록은 그대로 이용한다. 온라인 등록은 사용자가 명시적으로 선택하며, 이전 공유 연결이 있으면 먼저 기록을 유지한 채 연결 정보만 해제한다. 로그인 계정별로 아기와 요청을 구분한다.

- 새 아기 UUID·요청 UUID·지원되는 원본 스냅샷을 온라인 전송 전에 baby-atomic-connections에 보관하고 실제 저장 여부를 다시 확인한다. 사진·메모·발달 관찰과 다른 아기의 기록은 전송하지 않는다.
- 불확실한 통신 결과와 새로고침 뒤에도 동일한 ID·내용으로 재시도한다. 중복 클릭, 이미 연결된 아기의 재등록은 차단한다.
- 등록 직후 최신 서버 스냅샷을 읽고 원본 요청과 동일한 기록임을 확인한 경우에만 실제 읽은 버전을 연결 정보에 보관한다. 서버의 변경 기록을 기기에 자동 덮어쓰지 않는다.
- 통신 전후 계정·선택 아기·기록·레거시 연결 상태를 확인한다. 달라진 경우 수락하지 않으며 원래 요청을 남긴다. 등록 대기 중 내용이 달라진 경우 비교·조정 기능을 제공하기 전까지 자동 재등록하지 않는다.
- 저장 공간 부족 시 전송하지 않는다. 연결 정보 저장 실패는 기존 요청 상태로 복구해 같은 ID 재시도가 가능하다.
- 008 RPC에 선택적인 p_expected_user_id를 추가했다. UI에서 시작한 요청은 이를 반드시 보내며 서버 auth.uid()와 대조한다. 이는 소유자 지정이 아니라 요청 도중 다른 계정으로 바뀌는 상황의 거부 조건이다. 운영 미적용인 008 초안을 수정했다. 예전 초안을 검증 환경에 이미 적용했다면 3인자 함수를 제거하고 4인자 함수 권한을 검토하는 별도 마이그레이션이 필요하다.

## 공개 상태

NEXT_PUBLIC_ATOMIC_REGISTRATION_ENABLED=true인 검증 환경에서만 새 카드를 표시하고 등록을 허용한다. 기본값은 꺼짐이며 실제 프로젝트 환경 파일은 바꾸지 않았다. DB 007/008은 운영 미적용이다. 레거시 공유·자동 백업 중지는 계속 유지한다. 신규 연결은 기존 baby-sync 매핑에 넣지 않으므로 레거시 자동 전송이 시작되지 않는다.

최초 등록 확인을 자동 백업 완료로 표시하지 않는다. 이후 변경 내용 자동 전송·가족 초대·기존 서버 아기 복원·차이 비교/병합·새 연결 해제/계정 파기는 아직 후속이다.

## 검증

- 등록 흐름 13개: 기본 차단, 계정·아기 변경, 기기 기록 보존, 영속 재시도, 서버 차이, 중복 클릭, 저장 실패 전/후 복구 등.
- 등록 DB 14개, 생성 클라이언트 8개: 예상 계정과 실제 JWT가 다른 경우 거부를 추가했다.
- 기존 원자적 클라이언트 10개 및 공유 중지 10개 회귀 통과.
- 전체 ESLint 및 webpack 프로덕션 빌드(타입 검사 포함) 통과.

실제 JWT·서버 다중 세션 동시성·운영 앱 연결 검증과 전체 자동 백업 전환이 남아 있다. 실제 서버 데이터·권한·사용자 브라우저 기록을 변경하지 않았다. 커밋·푸시·배포하지 않았다.

## 다음 작업

1. 대기 중 로컬/서버 기록이 달라졌을 때 비교·수락·조정하는 UX와 요청 보존/정리 정책.
2. 연결된 계정·아기·기준 버전을 사용하는 원자적 자동 백업, 충돌·실패·재시도 UI 및 복원 연결.
3. 실제 JWT와 검증 DB에서 007/008 및 생성·권한·재시도 검증. 모든 호출 경로 전환 전 중지 정책을 해제하지 않는다.
