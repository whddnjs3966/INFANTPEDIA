# INFANTPEDIA 개발 인계 — 2026-11-02

## 현재 상태

STEP 6 저장·공유 안정화를 진행 중이다. 오늘 새 등록 → 기록 비교 → 자동 백업 → 목록·복원까지 로컬 구현과 검증 환경 연결을 진행했다. 기존 UI 방향은 유지했다.

**운영 클라우드 중지는 유지 중이다.** 새 SQL 007~010은 운영 미적용이며 실제 환경 파일을 바꾸지 않았다. 서버 데이터·권한·사용자 브라우저 기록을 변경하지 않았다. 커밋·푸시·배포하지 않았다. 앞서 삭제한 테스트 아기 25개를 다시 만들거나 이관하지 않았다.

## 오늘 개발한 내용

| 작업 | 구현한 동작 | 적용 범위 |
| --- | --- | --- |
| 새 아기 등록 | JWT 계정을 소유자로 사용해 아기·소유권·최초 스냅샷을 함께 저장. 실패 시 롤백, 동일 요청 중복 생성 방지 | SQL 008·클라이언트·검증 환경 UI |
| 등록 요청 보관 | 아기 UUID·요청 UUID·원본 내용을 전송 전에 저장. 실패·새로고침 뒤에도 동일 요청 재시도 | 계정·아기별 기기 저장소 |
| 기록 비교 | 프로필·성장 수치·날짜·접종·누락 항목의 차이 표시. 확인한 경우에만 기기 내용으로 서버 백업 갱신 | 등록 대기 및 연결 후 충돌 비교 |
| 자동 백업 | 아기별 켜기/끄기, 변경 대기·직렬 전송, 영속 요청과 기준 버전, 실패/재시도 표시 | 검증 환경에서 사용자가 켠 아기만 |
| 충돌·계정 보호 | 서버 버전이 다르면 중단. 계정·아기·연결 변경 후 늦은 응답 반영 방지. 서버에서 예상 계정과 JWT 대조 | SQL 009·클라이언트·동작 검사 |
| 백업 목록 | membership으로 접근 가능한 canonical 백업만 조회. 역할 표시와 UUID 커서 페이지 처리 | SQL 010·설정/첫 실행 화면 |
| 새 기기 복원 | 내용 확인 후 새 로컬 아기로 추가. 기존 기록·사진·메모 보존, 중복 복원 차단, 자동 백업은 꺼짐으로 시작 | 검증 환경 |
| 기기 저장 복구 | 네 저장소 변경을 저널에 먼저 기록. 중간 실패 롤백, 다음 문서 읽기 전 복구, 복구 실패 시 동작 중지 | 기기 로컬 저장소 |
| 읽기 전용 복원 | reader 역할 보존, 자동 전송 차단 및 읽기 전용 안내 | 복원된 아기 |

온라인 백업 범위는 프로필·성장 수치·접종 정보다. **사진·메모·발달 관찰은 서버 백업/복원 대상이 아니다.** 현재 비교는 명시적 기기→서버 전체 갱신이며 항목별 자동 병합이나 기존 로컬 아기 교체를 제공하지 않는다.

## 검증 결과

최신 복원 단계에서 실행한 회귀 검사 144개가 통과했다. 반복 실행된 각 단계의 검사 수를 더해 하루 전체 건수로 계산하지 않는다.

| 검사 | 통과 수 |
| --- | ---: |
| 복원 흐름 | 18 |
| 저널 복구 | 5 |
| 원자적 DB·권한·목록 | 31 |
| 등록·기록 비교 | 25 |
| 자동 백업 | 16 |
| 아기별 기록 | 22 |
| 클라우드 읽기 | 17 |
| 기존 공유 중지 | 10 |

전체 ESLint·TypeScript·webpack 프로덕션 빌드도 통과했다. 격리 QA 사본과 가짜 계정/서버로 390px 밝은 화면·360px 다크 모드, 취소·실패·재시도·충돌·새 기기 복원·기존 기록 보존을 확인하고 화면을 직접 검토했다. 운영 요청과 페이지 오류는 0건이었다. QA 개발 서버는 종료했다.

이는 실제 JWT·다중 DB 세션·실기기·여러 탭의 동시 복원 검증을 완료했다는 의미는 아니다. localStorage 저널은 브라우저 여러 탭 전체를 잠그는 DB 트랜잭션이 아니다. 기본 Turbopack의 기존 폰트 오류도 webpack 성공으로 해결 판정하지 않는다.

## 다음 개발 순서

1. **새 연결 해제**: 현재 계정·아기·서버 대상 확인, 대기 전송/늦은 응답 무효화, 로컬 기록 보존. 불확실한 요청을 무작정 버리지 않는 정책을 정한다.
2. **아기 삭제·계정 탈퇴**: 기기 삭제와 서버 파기를 구분한다. owner/editor/reader와 가족의 남은 접근권, request/membership/snapshot 외래키, 사진·메모·대기 요청의 처리까지 연결한다. 기존 삭제 경로를 그대로 사용하지 않는다.
3. **가족 공유**: 초대 생성·만료·취소·참여자 목록, 참여/해제와 권한 변경·철회를 새 프로토콜로 전환한다.
4. **기존 아기의 재연결·병합**: 새 아기 추가 외에 기존 로컬 아기 대상으로 복원/교체/항목별 병합을 설계하고 미리보기·취소·저장 실패 복구를 검증한다.
5. **검증 DB 및 실제 계정 검사**: 분리된 환경·백업 마련 → 007/008/009/010 적용 → 실제 JWT·동시 수정·권한 철회·네트워크 실패·복원/삭제 검증. 브라우저 다중 탭·실기기 저장 중단도 확인한다.
6. **전체 경로 전환·운영 적용 준비**: 관리자·생성·조회·복원·공유·삭제 호출을 점검하고 비활성 레거시 delete→insert 소스를 제거한다. 필요한 최소 권한과 기능만 공개하며 중지 플래그만 먼저 해제하지 않는다.
7. **콘텐츠와 공개 QA**: 건강 FAQ 검수대기 검증, 개월별 하루시간표 점검, 출처·위험 문구/발열 기준 검수, 온라인 팁·검색, 접근성·PWA·개인 데이터 캐시·부모 사용성 확인.
