# 테스트 데이터 소유권 점검

점검일: 2026-11-01 (Asia/Seoul)

사용자가 기존 DB에는 본인의 테스트 데이터만 있다고 확인했다. 임시 차단을 유지한 채 서버 역할로 최소 식별 열만 읽어 집계했다. 이름·이메일·기록 본문·키는 출력하거나 이 문서에 저장하지 않았다. DB 변경·삭제·권한 부여·007 적용은 하지 않았다.

## 확인 결과

| 대상 | 행 수 | 결과 |
| --- | ---: | --- |
| shared_babies | 25 | creator_id 없음 20개, 있음 5개 |
| shared_devices | 26 | 아기 연결 누락 0개, 생성자 없는 아기에 연결된 행 21개 |
| shared_measurements | 0 | 서버에 저장된 행 없음 |
| shared_vaccinations | 0 | 서버에 저장된 행 없음 |
| shared_daily_logs | 0 | 서버에 저장된 행 없음 |
| 인증 계정 | 4 | 관리자 사용자 조회에 반환된 계정 수 |

생성자가 있는 아기의 creator_id는 서로 다른 계정 2개를 가리키며 두 계정 모두 인증 사용자 목록에 존재했다. 전체 행 수와 조회 행 수를 대조했고 페이지 누락은 없었다. shared_devices의 기기 ID·헤더는 소유권 증명이 아니다.

서버 역할로 공유 테이블 5개를 읽는 요청 및 관리자 사용자 조회는 모두 HTTP 200이었다. 이는 해당 읽기 경로 확인이며 모든 서버 기능·쓰기 권한 검증은 아니다. 현재 서버 자식 기록이 0건인 것이 이전 기록의 삭제를 뜻하지 않는다. 차단 전 기준 행 수가 없어 보존 여부를 완전히 비교할 수 없으며, 브라우저 로컬 기록 수와도 별개다.

## 다음 순서

1. 유지할 테스트 아기 범위와 앞으로 사용할 소유자 계정을 확정한다. 본인 테스트 데이터라는 답변만으로 삭제·통합·일괄 소유권 부여를 하지 않는다.
2. 현재 DB와 브라우저 로컬 데이터를 백업하고, 확정한 명단으로 관리자용 membership·초기 스냅샷 이관안을 작성한다. creator_id만으로 자동 승인하지 않는다.
3. 007 및 새 프로토콜을 별도 검증 환경에서 적용하고 생성·공유·복원·전송·해제·삭제 경로를 함께 전환한다.
4. 로그인 역할 차단, 원자적 전송, 실패/재시도, 다중 기기 충돌·복원을 실제 환경에서 확인한 뒤 필요한 최소 접근만 연다.

익명 역할 차단과 공개 콘텐츠 유지 검증은 SHARING-PERMISSIONS-REVIEW-2026-11-01.md를 참고한다. 임시 차단은 계속 유지한다.
