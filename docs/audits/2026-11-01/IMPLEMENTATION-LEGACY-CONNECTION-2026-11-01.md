# 이전 공유 연결 정리

작업일: 2026-11-01 (Asia/Seoul)

## 변경 결과

서버 테스트 아기 삭제 후에도 브라우저에는 예전 공유 대상과 초대코드가 남을 수 있다. 기존 UI는 이를 '공유 연결됨'으로 표시하고 자동 백업을 시도했다. 현재 서버 권한은 임시 차단 상태이므로 조회 거부·빈 응답만으로 서버 삭제를 확정할 수 없다.

이제 가족 공유 화면은 기기 보관과 온라인 공유 일시 중지를 안내한다. 기존 초대코드를 유효한 코드처럼 표시하지 않고, 사용자가 확인창에서 '기록 유지하고 해제'를 선택하면 현재 아기의 브라우저 연결 정보만 제거한다. 로그인하지 않은 상태에서도 이 기기의 연결 정리는 가능하다. 아기·성장·접종·사진·메모 저장소는 수정하지 않는다.

- 확인 중 아기나 공유 대상이 바뀌면 오래된 해제를 거부한다. 대상이 바뀌면 확인창도 다시 열린 상태로 유지하지 않는다.
- 다른 아기의 연결은 보존하며 해제 결과를 baby-sync에 저장한다. 새로고침 후에도 해제 상태가 유지된다.
- 같은 대상의 대기 중 백업 토큰을 무효화한다. 늦게 도착한 이전 응답은 성공으로 표시하지 않는다.
- SyncManager는 중지 상태에서 전송 큐를 만들지 않는다. share/join/push/pull 함수도 네트워크·인증·기기 ID 생성 전에 중단하므로 다른 호출 경로에서 서버 아기를 재생성하거나 빈 기록을 가져오지 않는다.
- 데이터 보관 화면에서 중지 상태가 우선 표시되며 재시도와 예전 전송 완료 시각을 숨긴다. 온보딩의 초대 연결도 중지 안내와 비활성 상태를 표시한다. 새 아기의 로컬 등록은 계속 가능하다.

현재 공유 중지는 sharing-availability.ts의 명시적인 코드 정책이다. 안전한 새 프로토콜로 모든 경로를 전환하기 전 이를 해제하지 않는다. 공유 화면을 새 흐름으로 교체해야 하므로 정책 함수만 false로 바꾸는 방식으로 재개하지 않는다.

## 검증

- check:sharing-paused 10개 통과: 운영과 같은 중지 정책의 네트워크 차단, 저장소 보존, 대상 변경, 반복 해제, 영속 저장, 대기/늦은 전송 응답 무효화.
- check:backup 16개 및 check:cloud-read 17개 통과. 기존 서비스의 세부 오류 처리 검사는 테스트에서만 중지 정책을 우회해 비활성 레거시 구현을 검증한다. 운영에서 레거시 접근을 허용했다는 의미는 아니다.
- 전체 ESLint 및 webpack 프로덕션 빌드(타입 검사 포함) 통과. 마지막 화면 문구 변경 후 TypeScript/관련 파일 ESLint 재확인.
- 별도 가상 프로필·격리된 브라우저로 6가지 화면 동작 확인: 취소, 기록 보존 해제, 새로고침 유지, 재시도 미표시, 360px 다크 모드 가로 넘침 없음, 온보딩 초대 비활성. 390px 밝은 화면과 확인창도 캡처·시각 확인했다.
- 화면 QA 중 공유 테이블 요청 0건, pageerror 0건. 실제 사용자의 브라우저 저장소나 서버 기록을 변경하지 않았다. 기본 Turbopack의 과거 폰트 오류는 이번 webpack 빌드 결과로 해결했다고 판정하지 않는다.

## 후속 작업

1. 로그인 소유자·아기·revision 0 스냅샷을 함께 등록하는 새 서버 경로 구현.
2. 생성·공유·조회·복원·자동 백업 경로 동시 전환 및 로컬 기록의 명시적 재연결/수락 UX.
3. 실제 JWT 권한, 다중 세션 충돌, 저장 실패·재시도·새 기기 복원 검증.

자동 서버 삭제 판정이나 새 백업 연결은 이번 구현 범위에 포함되지 않는다. DB 권한/스키마 변경, 007 적용, 추가 데이터 삭제, 커밋·푸시·배포는 하지 않았다.
