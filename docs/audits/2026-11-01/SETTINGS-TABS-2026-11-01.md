# 설정 화면을 탭별 내용으로 전환

날짜: 2026-11-01 (Asia/Seoul)

## 반영

- 상단 내 계정/아기 관리/가족과 공유/앱 환경/데이터 관리를 선택 탭으로 변경했다. 선택한 패널 하나만 표시한다.
- 비활성 패널은 화면·키보드·접근성 트리에서 숨기되 컴포넌트는 유지해 입력 중인 내용을 보존한다.
- 선택 탭을 `#settings-babies` 등의 기존 주소와 연결했다. 직접 열기, 새로고침, 브라우저 뒤로/앞으로와 hash 기반 패널 간 링크를 지원한다.
- 선택 상태, tablist/tab/tabpanel 관계, 좌우 화살표·Home·End 키 이동, 단일 Tab 진입점을 제공한다.
- 다른 탭으로 전환하면 열려 있던 삭제 확인창을 닫는다. 실제 삭제·백업·공유 로직은 변경하지 않았다.
- 선택 후 상단 탭이 보이는 위치로 이동한다. 주소가 없는 첫 설정 화면은 내 계정을 표시한다.

## 검증

- 변경 파일 ESLint 오류/경고 0.
- 최종 `npm run build -- --webpack`: TypeScript 포함 프로덕션 빌드 통과.
- `#settings-babies` 직접 진입 시 아기 관리만 표시.
- 앱 환경으로 이동하면 다른 패널이 숨겨지고 해당 패널 하나만 표시.
- 아기 추가 폼의 임시 이름을 입력하고 앱 환경→브라우저 뒤로 이동 시 입력 유지 확인. 임시 입력을 비우고 취소했으며 새 아기를 저장하지 않았다.
- 좌우 키 중 ArrowRight로 아기 관리→가족과 공유 전환 및 포커스 이동 확인.
- 데이터 관리에서 새로고침 후 해당 탭 복원, ‘가족 공유 설정 확인’ 링크로 가족 탭 전환 확인.
- 360px 앱 환경 화면에서 가로 넘침 없음. 390px 아기 관리 화면 확인.

화면 증거: `step6-screenshots/settings-app-tab-360.png`, `settings-babies-tab-390.png`.

기존 STEP6 보고서의 세로 나열·앵커 바로가기는 이 탭 UI로 대체됐다. 실제 백업·복원·권한·서버 파기와 사용자 요청의 시간표/건강 FAQ 검증 TODO는 여전히 남아 있다. 커밋·푸시·배포하지 않았다.

## 추가 수정 — 최상단 유지와 탭 디자인 개선

반영일: 2026-11-01. 앞서 기록한 ‘선택 후 상단 탭이 보이는 위치로 이동’ 동작을 **설정 페이지 최상단 유지**로 교체했다.

- 2열·3행의 큰 탭 박스를 아이콘과 짧은 이름을 가진 동일 너비의 5열 메뉴로 교체했다. 선택 탭은 옅은 청록 배경·진한 글자/아이콘·밑줄로 구분한다. 스크린리더에는 기존 전체 이름을 유지한다.
- 탭 위치로 `scrollIntoView`하던 코드를 제거했다. 다른 탭과 같은 탭을 선택할 때 모두 페이지의 `scrollY=0`을 적용한다.
- 기존 hash 주소는 유지하되 패널 DOM ID를 분리해 브라우저의 앵커 이동이 설정 제목과 프로필을 화면 위로 밀어내지 않도록 했다.
- 직접 주소 열기·새로고침·브라우저 이력·패널 간 링크에서도 최상단을 적용한다. 브라우저의 전역 scrollRestoration 정책은 변경하지 않는다.
- 단일 패널 표시, 입력 유지, 키보드 탭 이동과 ARIA 연결은 유지했다.

검증: 변경 파일 ESLint 오류/경고 0, 최종 Webpack 프로덕션 빌드(TypeScript 포함) 통과, 공백 오류 없음. 실제 브라우저에서 다섯 탭과 같은 탭 재선택 후 top=0, 스크롤된 데이터 관리에서 가족 링크 이동·뒤로 가기·새로고침 후 top=0을 확인했다. Home 키 이동 시에도 포커스와 top=0을 확인했다. 360px에서 각 탭은 55×78px이며 가로 넘침이 없고, 390px에서도 한 줄로 표시된다. 확인한 탭의 브라우저 오류 로그는 없었다.

최신 화면 증거: `step6-screenshots/settings-tabs-refresh-360.png`, `settings-tabs-refresh-390.png`. 기존 탭 스크린샷은 이전 디자인 기록이다. 코드 변경은 `src/app/settings/page.tsx`이며 커밋·푸시·배포하지 않았다.
