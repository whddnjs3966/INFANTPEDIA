# STEP 6 2차 — 아기별 온라인 전송 상태와 재시도

날짜: 2026-11-01 (Asia/Seoul)

## 구현

- 데이터 관리에 기기 보관 / 온라인 대기 / 전송 중 / 전송 완료 / 실패 / 확인 필요를 구분했다. 실패·확인 필요 상태에서 현재 계정의 연결된 아기를 다시 시도할 수 있다.
- 아기 ID·로그인 계정·공유 대상별 상태를 구분한다. 이전 계정이나 공유 대상의 성공 시각을 새 연결에 재사용하지 않는다.
- 변경이 있을 때 3초 대기 후 기존 직렬 전송 큐를 사용한다. 전송 중 재시도 버튼을 표시하지 않는다.
- 서버로 확인한 로그인 계정이 현재 계정과 같은 경우만 업로드한다. 비로그인·공유 연결 없는 상태에서는 전송을 시작하지 않는다.
- 시도별 토큰으로 변경·아기 전환·계정 변경·연결 해제 후 늦게 도착한 응답이 최신 상태를 덮어쓰지 못하게 했다.
- 프로필 업로드는 실제 반환된 행 ID를 확인하고, 측정·접종 갱신의 삭제/삽입 오류도 실패로 처리한다. 실패를 성공 시각으로 저장하지 않는다.
- 상태와 확인 시각은 런타임 메모리에서 관리한다. 새 세션에 오래된 ‘완료’를 물려주지 않는다. 기존 전역 lastSyncAt은 호환용으로 유지하지만 현재 아기의 완료 표시에는 사용하지 않는다.
- 전송 범위를 **프로필·성장 수치·접종 정보**로 명시했다. 사진·측정 메모·발달 관찰은 전송 범위에 포함하지 않는다. 이 기능은 새 기기 복원 구현과 별개다.

## 검증

- 변경 파일 ESLint 오류/경고 0, TypeScript 검사 및 최종 Webpack 프로덕션 빌드 통과.
- `npm run check:backup`: 실제 TS 상태 저장소·실행기·전송 서비스를 모의 인증/DB로 실행한 회귀 검사 16개 통과.
- 검사 범위: 성공·인증 거부·통신/서버 실패·계정별 재시도·중복 재시도 차단·진행 취소·오래된 성공 응답 무시·계정/공유 대상 변경·업로드 각 단계 실패·프로필 행 0건·빈 기록 전송.
- `npm run check:ux`: 기존 날짜·아기별 기록 검사 13개 통과.
- 로컬 브라우저에서 비로그인 상태가 ‘기기에서만 관리 중’으로 표시되고 전송 범위가 보이는지 확인. 360/390px에서 가로 넘침 없음.
- 로컬 QA 프록시 쓰기 요청 0건. 실제 사용자 기록을 생성하거나 운영 서버 백업을 실행하지 않았다.

## 남은 검증과 제한

실제 Supabase 연결, 로그인 사용자 화면에서의 실패·재시도, 두 기기 복원은 검증하지 않았다. 온라인 성공/실패 경로는 모의 인증/DB 회귀 검사 결과이며 실서비스 연동 완료를 뜻하지 않는다.

기존 전송 서비스의 delete→insert 교체 방식은 아직 서버 트랜잭션이 아니다. 부분 실패 및 여러 보호자의 동시 수정에서 서버 데이터 유실을 막는 원자적 갱신·충돌 처리는 후속 과제다. 로컬 기록은 이 전송 과정에서 삭제하지 않는다. 가족 RLS/권한·초대/해제·서버 파기, 사진/메모/관찰 백업 확장도 별도다.

다음은 **안전한 클라우드 갱신·로그인 후 복원 설계와 연동**이며, 실제 서버 테스트 전 Supabase 연결과 권한을 확인해야 한다. 요청한 시간표/건강 FAQ 검증 TODO는 그대로 미완료다.
