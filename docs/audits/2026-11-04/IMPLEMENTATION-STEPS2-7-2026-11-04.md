## 2. 삭제와 탈퇴

- 설정 → 데이터 관리에서 아기 한 명의 기기 기록 삭제, 전체 기기 초기화, 현재 백업의 서버 삭제, 계정 삭제를 구분했다. 이름/‘전체 삭제’/‘계정 삭제’ 입력 후 명시적으로 실행한다.
- 기기 삭제는 해당 프로필·사진·성장·메모·접종·관찰과 연결/해제 이력·미확정 요청·초대 요청을 정리한다. 다른 아기와 서버는 유지한다. 계정 연결 정리 역시 다른 계정의 요청을 보존한다.
- 서버 아기 삭제는 owner와 확인한 revision만 허용한다. 스냅샷·멤버십·생성 영수증·초대·관련 레거시 자식을 한 트랜잭션에서 지우고 tombstone으로 과거 등록 재생을 막는다. 기기 기록은 남기고 연결은 제거한다.
- 계정 삭제는 소유 백업과 타인 소유 백업 접근을 먼저 보여 준다. 확인 manifest가 바뀌면 중단하고, 소유권을 확인하지 못한 레거시 참조는 파기하지 않는다. 계정의 새 쓰기를 막은 뒤 서비스 역할로 데이터를 정리하고 마지막에 Auth 사용자를 삭제한다.
- 최근 15분 이내 로그인, 현재 계정 일치, 요청 Origin/Host 일치, 요청/결과 ID 일치를 검사한다. Next의 내부 localhost 정규화와 브라우저의 127.0.0.1 주소 차이를 실제 통합 검사에서 수정했다.
- 네트워크 결과 유실과 Auth 삭제 실패에는 같은 요청 ID를 유지한다. 서버 정리 완료/로그인 삭제 대기 상태를 구분해 재개한다. 기기 기록의 동시 삭제는 기본 선택이 아니며 전체 브라우저 범위를 별도로 표시한다.

## 3. 가족 공유

- 로그인 계정 이메일을 지정하고 reader/editor 권한으로 초대한다. 기존 계정만 수신자로 지정할 수 있다. 코드 유효 시간은 24시간이고 원문 코드는 서버에 저장하지 않는다.
- 초대는 지정 수신자만 수락할 수 있다. 동일 요청의 정확한 재시도는 중복 초대를 만들지 않으며, 철회/만료된 초대와 탈퇴 후 옛 코드 재생을 거절한다.
- 소유자가 참여자·초대를 확인하고 권한 변경·접근 해제·초대 취소를 수행한다. 확인한 초대 뒤에 다른 가족도 추가할 수 있다. 본인의 owner 권한 제거/이전은 이 경로에서 허용하지 않는다.
- 비소유자는 공유에서 나갈 수 있다. 서버 접근을 해제하고 기기 연결을 끊으며 이미 각 기기에 저장한 기록을 원격 삭제하지 않는다.
- 공유를 수락해도 기기 기록을 자동 교체하거나 자동 전송하지 않는다. 백업 목록에서 내용을 확인해 가져온다.

## 4. 현재 아기에 가져오기

- 설정 → 가족 → 백업 목록 → ‘현재 아기와 비교해 가져오기’에서 비교한다. 새 아기로 추가하는 기존 복원도 유지한다.
- 이름/생년월일/성별과 성장 기록, 백신별 차수를 선택한다. 기본은 기기의 기존 항목을 남기면서 서버에만 있는 항목을 추가한다. 서버 내용으로 교체는 별도 선택이다.
- 반영할 아기 이름을 입력하고 확인한다. 확인 직전에 계정·현재 아기·기기 기록/대기 요청·서버 버전/내용을 다시 대조한다. 없는 항목 선택과 잘못된 날짜를 거절한다.
- 다른 아기·사진·발달 관찰과 남긴 성장 항목의 메모는 유지한다. 제외한 측정 항목의 메모는 함께 제외됨을 표시한다. 생년월일이 기존 관찰일보다 늦어지면 거절한다.
- 실제 서버 기준 스냅샷과 revision을 수락한다. 기기 병합 결과가 다르면 비교 필요 상태로 두며 자동 백업은 꺼진다. 병합 자체는 서버에 쓰지 않는다.

### 분리 DB와 백업

- PostgreSQL 17.11을 `127.0.0.1:55439`에서 별도 프로세스로 실행했다. 운영 URL로 전달/프록시하지 않았다. 004/005 기반 합성 스키마에 007 → 008 → 009 → 010 → 011 및 기존 중지 정책을 적용했다.
- 반복 읽기 전용 트랜잭션으로 12개 테이블과 마이그레이션 SQL을 논리 내보내고 **다른 신규 DB**에 복원했다. 전 값과 복원 후 anon 거절/owner 읽기를 확인했다. 경로·SHA256·DB 이름은 `local-stage-backup.json`에 남겼다.
- 이 백업은 합성 Auth 스키마를 포함한 로컬 논리 fixture다. `pg_dump` 또는 실제 Supabase Auth/Storage/운영 백업의 복구 검증으로 간주하지 않는다.
- 실제 PostgreSQL의 별도 연결로 같은 revision의 두 쓰기, 동시 동일 재시도, 쓰기→철회와 철회→쓰기 양방향 경합을 확인했다. 정확한 재시도는 revision을 한 번만 올리고, 나머지 쓰기는 충돌 또는 권한 거절로 끝난다.

### JWT·브라우저·기기 저장

- 로컬 RSA 키로 서명한 JWT를 검증하는 loopback 게이트웨이와 실제 PostgreSQL RPC를 격리 Next 앱에 연결했다. 유효 토큰·만료·변조·서비스 역할 위조 거절 검사를 수행했다. 이 서버는 실제 Supabase Auth/GoTrue/PostgREST를 대신 검증한 것이 아니다.
- 별도 브라우저 컨텍스트로 수신자 참여/첫 복원, owner 권한 변경/철회, 기존 아기 병합, 서버/기기 삭제, 실제 Next 계정 삭제 API와 합성 Auth 행 삭제를 확인했다. 다른 소유자의 백업과 기본 기기 기록이 유지됐다.
- 다른 탭의 기기 저장 변경이 감지되면 오래된 탭의 UI/새 온라인 작업을 중지하고 새 문서로 불러오게 했다. 이미 보낸 서버 요청은 완료될 수 있다. 저장 이벤트 감지만으로 모든 브라우저의 극도로 가까운 동시 쓰기에 직렬성을 보장한다고 주장하지 않는다.
- 저널은 9개 대상 키의 사전 값을 기록하고 저장/검증 후 commit한다. 중간 실패는 롤백하고, committed 중단은 완료 방향으로 복구한다. 새 탭이 실행 중인 다른 문서의 prepared 저널을 즉시 되돌리지 않도록 10초 보호 구간을 두었다.
- 실제 브라우저의 저장 예외를 주입해 중간 삭제 롤백, 중단 저널 복구, 지속 실패 시 화면/동기화 차단과 저장 정상화 후 재시작을 확인했다.
- Chrome 360/390/430px, 200% 루트 글자 확대, 다크 모드에서 이번 화면을 확인했다. 글자 확대 시 설정 탭 라벨이 인접 탭에 겹치던 부분과 긴 아기 이름의 삭제 버튼 배치를 수정했다. 전체 접근성 인증이나 실제 OS 글자 크기 검증은 아니다.
