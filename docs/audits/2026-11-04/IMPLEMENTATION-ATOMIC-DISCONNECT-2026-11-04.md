# 새 백업 연결 해제·같은 백업 재연결

작성: 2026-11-04 (Asia/Seoul)

## 문서 확인과 작업 범위

저장소의 MD 목록·기획/로드맵·감사/구현 문서·TODO를 읽고, 최신 인계(2026-11-02)를 현재 상태의 기준으로 삼았다. 예전 문서에 남은 검색·다크 모드 등의 미완료 표기를 새 기능 요구로 다시 구현하지 않았다. 다음 순서였던 새 연결 해제를 진행했고, 해제 후 중복 서버 생성 없이 같은 백업을 다시 확인하는 경로도 추가했다.

## 구현 결과

- 가족/데이터 화면에서 현재 아기와 연결된 백업 이름·생일을 확인하고 '이 기기의 백업 연결 해제'를 선택한다. 기기 아기·기록·사진·메모는 유지하며 서버 삭제·가족 권한 철회·다른 기기 연결 변경이 아님을 명시한다.
- 로그인 계정·현재 아기·서버 ID·연결 ID·기준 버전 등을 대조한다. 확인 도중 다른 연결/계정/아기로 바뀌면 해제하지 않는다.
- 한 번의 연결 저장으로 활성 대상을 제거하고 이전 연결을 보관한다. 자동 전송 outbox와 기록 비교 요청은 버리지 않는다. 이미 전송한 요청은 서버에서 끝날 수 있지만 늦은 응답이 해제된 연결을 다시 살리지 못한다.
- 해제 상태는 새로고침 후에도 유지된다. 이전 백업이 있는 같은 계정/아기를 새 서버 아기로 자동 재등록하지 않는다.
- '이전 백업 확인하고 다시 연결'은 원래 서버 ID를 읽고 계정별 목록에서 현재 접근 역할도 확인한다. 서버·기기 기록을 덮어쓰지 않으며 자동 백업은 꺼짐으로 시작한다. 접근이 철회됐거나 읽기에 실패하면 이전 연결 정보를 유지한다.
- 기록 차이·미확정 요청이 있으면 requiresReview로 보관하고 명시적인 기록 비교/수락 전 자동 쓰기를 막는다. 정상 비교/수락 후 관련 outbox를 정리한다. reader로 권한이 낮아진 경우 읽기 전용으로 복구한다.
- 다른 탭의 저장값 변경을 오래된 해제 요청이나 늦은 자동 백업 응답이 덮어쓰지 않도록 저장 상태를 대조한다. JSON 속성 순서만 다른 경우는 실제 내용 변경으로 오판하지 않는다.
- 다른 아기를 복원할 때도 해제 이력·미확정 요청 정보를 보존한다. 해제/재연결 저장 실패는 이전 메모리·저장 상태 복구를 시도하고 성공으로 표시하지 않는다.

## 공개 상태와 남은 한계

기존 NEXT_PUBLIC_ATOMIC_REGISTRATION_ENABLED 검증 플래그 안에서만 제공한다. 실제 환경·서버 데이터·권한·SQL은 변경하지 않았다. 운영 클라우드/레거시 중지는 유지하며 커밋·푸시·배포하지 않았다.

해제 이력과 미확정 요청은 보존하므로 향후 아기/계정 삭제 시 해당 저장소도 처리해야 한다. 최초 등록 대기 자체의 취소, 서버 권한 철회·백업 파기, 다른 기기의 전송 중단은 이번 기능이 아니다. 모의 저장값 변경 검사는 전체 실제 다중 탭 경쟁 조건 검증을 대신하지 않는다.
