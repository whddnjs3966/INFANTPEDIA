# InfantPedia UI/UX 중심 개선 실행안

작성일: 2026-10-29 · 대상: 로컬 main / aa2aec8

**개선 목표: 부모가 첫 화면에서 현재 아기를 확인하고, 필요한 정보와 기록 기능에 빠르게 도달하며, 저장 결과를 믿을 수 있게 만든다.**

기존 QA 캡처와 화면 구현 코드를 추가로 검토해 작성했다. 아래 본문은 최초 분석 시점의 제안과 완료 기준이다. 이후 구현과 로컬 QA 현황은 진행 업데이트와 진행표에 기록한다. 부모 대상 사용성 관찰은 아직 별도 검증 과제다. 기존 전체 기술 분석은 [앱 분석 보고서](D:/workplace/03-INFANTPEDIA/docs/audits/2026-10-29/INFANTPEDIA-AUDIT-2026-10-29.md)를 참고한다.


> **2026-10-30 진행 업데이트:** 공통 UI·홈·백과/기록/생활 자료의 1·2차 개선을 반영했고 사용자가 전체 UI에 만족한다고 확인했다. 아래 현재 관찰은 최초 분석 시점의 기준이다. **STEP 3 / UX-11 탐색 복귀**에 이어 **STEP 4의 기록 화면 아기 전환·관찰일 편집·임시 입력 복구**를 구현하고 로컬 검증했다. 다음은 **STEP 5의 생활 자료 상태 유지와 건강 정보 출처·검수 상태 표시**다. 최신 상태와 남은 항목은 [진행표](./UIUX-PROGRESS.csv), 검증 근거는 [STEP 3 구현 보고서](../2026-10-30/IMPLEMENTATION-STEP3-2026-10-30.md)와 [STEP 4 구현 보고서](../2026-10-30/IMPLEMENTATION-STEP4-2026-10-30.md)를 따른다. 전체 접근성·서버·의료 검수 완료를 뜻하지 않는다.
## 1. 한눈에 보는 작업 순서

| 순서 | 작업 | 가장 먼저 바꿀 것 | 완료 시 사용자 경험 |
|---|---|---|---|
| STEP 1 | 공통 UI와 정보구조 | 글자·대비·버튼·탭 역할 통일 | 어느 화면에서나 읽고 누르는 방법이 같음 |
| STEP 2 | 홈·첫 실행 | 큰 일수 카드 축소, 검색·기록·현재 아기 상단 배치 | 처음 들어와 바로 할 일을 찾음 |
| STEP 3 | 백과·검색 | 숨은 주제를 펼쳐 보여주고 월령/탭/스크롤 기억 | 필요한 글을 찾고 원래 위치로 돌아옴 |
| STEP 4 | 성장·예방접종 | 내 기록의 변화와 입력·수정 흐름 우선 | 누구의 기록인지 분명하고 실수를 고칠 수 있음 |
| STEP 5 | 건강·생활 꿀팁 | 증상별 탐색, 월령에 맞는 시간표·식단 | 상황에 맞는 정보를 이해하고 사용함 |
| STEP 6 | 설정·가족 공유 | 계정/아기/가족 역할 분리, 저장 상태 표시 | 무엇이 저장·공유되는지 이해함 |
| STEP 7 | 실제 사용 흐름 검증 | 작은 화면·키보드·뒤로 가기·실패 복구·다크 모드 | 주요 작업을 도움 없이 끝냄 |

UI/UX 설계와 화면 개편을 이 순서로 진행한다. 기존에 발견한 관리자 인증·가족 권한·의료 콘텐츠 문제는 각 기능의 공개 완료 조건에 포함한다. 아기별 기록 혼합은 기록 화면을 개선할 때 함께 수정해야 한다.

**첫 구현 묶음은 STEP 1과 STEP 2를 권장한다.** 홈과 공통 컴포넌트를 한 번 완성하면 나머지 화면의 기준이 생긴다.

## 2. 사용 목적과 메뉴 역할부터 정리

한 손으로 짧게 확인하거나 야간에 사용하는 상황을 설계 가정으로 둔다. 실제 이용 환경과 우선순위는 후속 사용자 관찰에서 확인한다.

핵심 사용자 행동은 세 가지다.

1. **지금 필요한 정보 찾기**: 월령에 맞는 가이드, 증상 관련 글, 식단/시간표.
2. **아기 기록 확인·추가**: 키·몸무게·머리둘레, 접종 완료, 발달 관찰.
3. **가족과 기록 관리**: 현재 아기 선택, 저장 상태 확인, 공유 참여/해제.

현재 5개 하단 탭은 유지할 수 있다. 역할의 중복을 먼저 줄인다.

| 탭 제안 | 담당 역할 | 정리할 부분 |
|---|---|---|
| 홈 | 현재 아기, 다음 행동, 최근 기록과 맞춤 정보 요약 | 같은 수치·일수 반복과 큰 장식 영역 축소 |
| 백과 | 수면·수유·이유식·놀이·치아·건강·발달의 상세 정보 | 주제를 눈에 보이게 하고 모든 콘텐츠의 상세 진입점 제공 |
| 기록 | 성장 기록과 예방접종 | 현재 '성장' 탭의 범위를 이름으로 설명. 새 수유/수면 일지를 이번 범위에 추가하지 않음 |
| 꿀팁 | 바로 참고할 하루 시간표와 식단 등 생활 자료 | 백과와 같은 설명을 반복하지 않고 관련 상세에 연결 |
| 설정 | 계정, 아기 관리, 가족 공유, 앱 환경 | 자주 쓰는 아기 전환은 홈과 기록에서도 제공 |

탭 이름 변경은 제안이다. '기록'이 성장과 예방접종을 모두 포함한다고 사용자에게 이해되는지 확인하고 확정한다.

## 3. STEP 1 — 공통 디자인과 조작 규칙

### 현재 관찰

- 주요 화면의 청록색과 둥근 카드 방향은 일관된다.
- 10~13px 텍스트와 옅은 회색 안내가 많다. 중요한 정보도 보조 정보처럼 보인다.
- 흰색과 브랜드 청록 `#14B8A6`의 계산상 대비는 약 2.49:1이다.
- 카드 안의 카드, 큰 여백, 반복된 소개 문장이 실제 내용의 첫 노출을 늦춘다.
- 이미지 변경·일부 닫기/복사/삭제 등 아이콘 동작의 접근 가능한 이름과 크기 규칙이 일관되지 않다.

### 변경안

| 요소 | 제품 디자인 목표 | 적용 예 |
|---|---|---|
| 본문 | 기본 16px, 긴 글 줄간격 약 1.6 | FAQ 답변·가이드 설명 |
| 핵심 라벨·보조 설명 | 14px 중심. 중요한 안내는 작은 캡션으로 처리하지 않음 | 단위·측정일·저장 상태 |
| 제목 | 화면 24~28px, 섹션 18~20px, 카드 16px를 기준으로 정리 | 화면마다 별도 크기를 늘리지 않음 |
| 주요 버튼 | 높이 48~52px, 명확한 동사 | '성장 기록 추가', '접종일 저장' |
| 아이콘 버튼 | 유효 터치 영역 48px 목표, 화면/스크린리더 이름 제공 | '기록 닫기', '공유 코드 복사' |
| 강조색 | 현재 청록은 브랜드·선택 강조, 흰 글자 버튼에는 더 진한 청록 검토 | 실제 렌더링 색으로 대비 재측정 |
| 카드 | 요약 카드·목록 행·읽기 본문·입력 시트로 용도 구분 | 매 문단을 둥근 카드로 감싸지 않음 |
| 여백 | 4/8/12/16/24/32px 중심으로 통일 | 모바일 좌우 20px 기준, 중요한 곳만 넓게 |
| 모션 | 짧은 상태 전환 중심, 반복 장식 모션 줄이기 | reduced-motion에서 반복/큰 이동 제거 |
| 하단 내비게이션 | 누르기 쉬운 영역, 현재 탭 이름·선택 상태 제공 | 본문 마지막 버튼과 겹치지 않게 여유 확보 |

크기 수치는 본 제품의 제안값이다. W3C의 일반 텍스트 대비 기준은 4.5:1, 큰 텍스트는 3:1이며 텍스트는 200% 확대를 지원해야 한다. 위의 '48px'과 '본문 16px'는 WCAG 최소 규정이라고 주장하는 값이 아니다. [W3C 대비 안내](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [W3C 확대 안내](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

### 완료 기준

- 대표 화면의 제목·본문·버튼·목록·입력·오류 상태가 같은 규칙을 사용한다.
- 360px 폭과 글자 확대에서 중요한 정보가 잘리거나 가려지지 않는다.
- 입력 시트가 하단 탭보다 앞에 보이고, 키보드가 떠도 입력·저장을 끝낼 수 있다.

## 4. STEP 2 — 홈·첫 실행

### 홈의 핵심 문제

현재 390px 캡처에서 프로필 다음에 큰 생후 일수 카드가 나오고, '오늘의 포커스'와 '월령 데이터'가 뒤따른다. 성장 기록 추가와 검색이 첫 화면의 주요 행동으로 드러나지 않는다. 생후 일수·개월·주수·이번 달 진행률은 같은 시간 정보를 반복해 보여준다.

부모가 '앱을 켠 다음 무엇을 할지' 바로 알 수 있게 정보의 순서를 바꾼다.

### 홈 배치 제안

| 위에서부터 | 표시 내용 | 조작 |
|---|---|---|
| 1 | 사진 · 아기 이름 ▼ · 만 개월/생후 N일 | 아기 전환 |
| 2 | '궁금한 육아 정보를 검색하세요' | 전체 콘텐츠 검색 |
| 3 | '성장 기록 추가' / '접종 기록' | 기존 기록 기능으로 바로 이동 |
| 4 | 오늘 확인할 일정·접종 안내 1~2개 | 해당 상세로 이동 |
| 5 | 최근 측정값·측정일·변화 요약 | 성장 기록 보기 |
| 6 | 이 월령의 추천 놀이·가이드 2~3개 | 해당 주제와 월령을 바로 열기 |
| 7 | 원더윅스 등 추가 참고 정보 | 필요할 때 펼쳐 보기 |

- 생후 숫자는 상단에 작게 남겨 기념성과 개인화를 유지한다.
- '이번 달 진행 0%'는 사용자가 행동하거나 이해할 정보가 적어 기본 홈에서 제외한다.
- 첫 화면에는 실제로 조작할 수 있는 기록/검색을 배치한다. 원격 정보가 실패해도 로컬 기록 행동은 사용할 수 있어야 한다.
- 월령 정보는 평균/참고 정보임을 설명하고 실제 수유 기록처럼 보이지 않게 한다.
- 사진 버튼과 아기 전환 버튼은 동작을 구분한다. 사진을 눌러 다른 아기를 찾게 만들지 않는다.
- 추천 가이드는 제목·대상 월령·짧은 이유를 보여주고 상세 메뉴까지 직접 연결한다.

### 첫 실행 변경안

- '월령에 맞는 정보 보기'와 '성장 기록 남기기'라는 사용 가치를 짧게 설명한다.
- **'아기 등록하기'와 '먼저 둘러보기'**를 제공한다. 공개 육아 정보 열람에는 프로필 입력을 강제하지 않는 구조를 제안한다.
- 이름 필드는 '아기 이름 또는 애칭'으로 안내한다.
- 생년월일·성별을 묻는 이유를 간단히 설명한다. 성별 미선택을 허용하려면 성장 기준 제공 방식도 함께 정해야 한다.
- 로그인은 실제 백업/가족 공유 기능을 사용할 때 자연스럽게 안내한다.
- 등록 후 바로 홈에 진입하고, 저장 방식 안내를 현재 구현과 일치시킨다.

### 완료 기준

- 390×844 기본 화면에서 현재 아기·월령·기록 추가·검색 진입을 찾을 수 있다.
- 홈의 이유식/수면 바로가기는 해당 상세 주제와 선택 월령을 그대로 연다.
- 처음 보는 사용자에게 '지금 할 수 있는 일'을 물었을 때 두 가지 이상을 찾아낼 수 있는지 확인한다. 이는 후속 검증 과제다.

## 5. STEP 3 — 백과·검색

### 현재 관찰

- 주제 8개와 월령 13개를 별도의 가로 줄에서 선택한다. 건강 FAQ·치아 등은 가로로 이동해야 발견된다.
- 페이지 제목·소개·주제·월령·검색/필터가 쌓여 실제 콘텐츠가 아래로 밀린다.
- 하위 탭과 월령이 URL에 반영되지 않아 다른 화면을 다녀온 뒤 맥락을 잃기 쉽다.
- 검색은 DB의 백과/꿀팁만 대상으로 하고 정적 건강 FAQ·수면·수유 가이드를 놓친다.
- 검색 결과는 잘린 설명 중심이며 원문을 여는 행동이 연결되지 않았다.

### 변경안

1. 백과 첫 화면은 '현재 아기 월령 ▼'와 검색, 주제 목록을 보여준다.
2. 수면·수유·이유식·놀이·발달·치아·건강을 두 열 또는 줄바꿈 가능한 목록으로 보여준다. 중요 주제를 가로 스크롤 뒤에만 두지 않는다.
3. 상세 화면에서는 주제 제목과 현재 월령을 간결하게 유지하고, 긴 소개는 줄인다.
4. 월령 선택은 '우리 아기 월령으로' 복귀 기능을 제공한다. 다른 월령을 탐색 중임을 문장으로 보여준다.
5. 검색 범위를 FAQ와 모든 가이드로 확장한다. 결과에 제목·주제·대상 월령·요약을 보여주고 원문을 연다.
6. '우리 아기 월령'과 '전체 월령' 검색을 구분한다. 전체 검색에서 다른 월령의 결과를 보여줄 때 대상 연령을 표시한다.
7. 상세→뒤로 가기에서 검색어·선택 월령·주제·목록 위치를 복원한다.
8. 데이터 없음, 검색어 일치 없음, 서버 연결 실패를 서로 다른 상태로 표시한다.

### 완료 기준

- 백과 진입 후 2회 이내 선택으로 원하는 주제의 글 목록을 연다. 전체 하위 항목이 2회 이내라는 의미는 아니다.
- 검색 결과에서 상세 본문을 열고 뒤로 돌아오면 이전 검색과 목록 위치가 유지된다.
- 같은 콘텐츠를 통합검색과 주제별 탐색 어느 쪽으로도 찾을 수 있다.

## 6. STEP 4 — 성장 기록·예방접종·발달 체크

### 성장 화면 배치

현재 첫 화면에는 큰 성장 현황 카드, 항목별 백분위, WHO 수치 비교 카드가 먼저 나온다. 차트와 기록 추가 버튼이 아래로 밀리고 같은 측정값이 반복된다. '상위 N%'를 강조하면 순위나 진단처럼 받아들일 가능성이 있어 표현 검토가 필요하다. 실제 사용자 반응을 관찰한 결과는 아니다.

제안 순서: **현재 아기 ▼ → 최근 측정일/수치와 '기록 추가' → 차트 → 기록 목록 → 성장 기준 설명**.

- 가장 최근 값과 측정일을 함께 보여준다. 오래된 기록을 현재 수치처럼 표시하지 않는다.
- 비교 정보는 필요할 때 펼쳐 본다. 기본은 내 기록의 시간에 따른 변화다.
- 추정 백분위는 계산 방식과 한계를 설명한다. '정상/비정상' 판단으로 읽힐 문구는 전문가 검수와 함께 정리한다.
- 차트 축·단위·범례를 키우고 색 이외에 선 모양/직접 라벨로도 구분한다.

### 측정 입력 흐름

**아기 확인 → 측정 날짜 → 키/몸무게/머리둘레 → 메모(선택) → 저장 결과 확인** 순서로 만든다.

- 측정 날짜로 월령을 계산해 보여준다. 생후 2개월 기록인지 사용자가 따로 맞추게 하지 않는다.
- WHO 평균값을 입력 예시로 강조하기보다 '측정한 값을 입력하세요'를 사용한다. 참고 기준은 도움말로 이동한다.
- 입력 중 한 항목만 저장할 수 있다는 점을 설명한다.
- 단위는 입력칸 밖에 고정하고 필드별 오류를 바로 가까이에 표시한다.
- 저장 중/완료 시 재클릭을 막아 중복 기록을 방지한다. 현재는 saved 상태에도 저장 버튼이 계속 활성화된다.
- 저장 후 기록 목록/차트에 반영하고 '기기에 저장됨'과 '클라우드 백업 완료'를 실제 상태대로 구분한다.
- 수정 기능을 제공하고 삭제는 되돌리기 또는 확인 과정을 둔다. 현재 목록은 휴지통 한 번으로 바로 삭제한다.
- 입력 중 닫기/뒤로 가기에는 작성 중 데이터가 있으면 보존하거나 폐기 여부를 확인한다.
- 시트와 하단 탭이 모두 z-50인 현재 코드는 겹침 가능성이 있어 레이어 규칙을 정리한다. 새 실기기 재현 결과는 아니다.

### 예방접종

- 첫 화면은 '이번 시기', '예정', '완료'로 정리하고 전체 백신 목록은 추가로 연다.
- 완료할 때 실제 접종일을 입력/수정할 수 있게 한다. 버튼을 누른 오늘이 자동으로 실제 접종일이 되지 않게 한다.
- 어떤 백신의 몇 차 접종인지 포함하는 접근 가능한 체크 이름과 상태를 제공한다.
- 완료 취소는 되돌릴 수 있게 하고 차수별 정보와 일정을 읽기 쉬운 한 줄 구조로 정리한다.

### 발달 체크

- '달성률' 중심 표현을 '관찰한 변화' 등 관찰 기록 중심으로 검토한다.
- 완료일을 확인·수정하고, 아기별 상태가 정확하게 나뉘어야 한다.
- 월령 전체 초기화는 일상 체크 동작과 떨어뜨리고 범위를 설명한다.

### 완료 기준

- 다른 아기로 전환했을 때 홈·성장·접종·발달에 이전 아기 기록이 나타나지 않는다.
- 입력·수정·오류 수정·삭제 취소·새로고침까지 같은 기록과 날짜가 유지된다.
- 키보드가 열린 상태에서 저장 버튼에 접근할 수 있다. VoiceOver/TalkBack에서 각 입력의 이름과 단위를 알 수 있다.

## 7. STEP 5 — 건강 FAQ·생활 꿀팁

### 건강 FAQ

현재 2개월 화면은 전체 74개 중 응급 그룹 12개를 위에 나열한다. 실제 증상에 대한 질문과 예방/참고 지식이 같은 긴급도 그룹에 들어 있어 '지금 응급 상황이라고 판단된 것인지' 오해할 수 있다.

- 첫 화면은 **증상·주제 검색 → 주제 선택 → 관련 질문 목록**으로 정리한다.
- 전문가가 검수한 긴급 안내는 명확히 보이게 유지한다. 관련 없는 응급 질문을 모든 사용자에게 길게 나열하는 방식은 재검토한다.
- 일반적인 안내 문서와 개인의 현재 상태에 대한 판단을 혼동하지 않도록 문구를 정리한다.
- 답변은 '핵심 요약 → 구체적 설명 → 상담/진료가 필요한 조건'처럼 읽기 쉬운 순서를 사용한다. 실제 판단 기준과 문구는 의료 검수가 선행되어야 한다.
- 대상 월령, 출처, 검수일을 표시한다. 월령이 다른 결과를 검색했다면 이를 숨기지 않는다.
- 위험 신호는 색과 텍스트를 함께 사용한다. 긴급 안내는 작고 옅은 보조 문구로 처리하지 않는다.

자동 진단·개인별 응급도 판정 기능을 새로 만드는 제안은 아니다. 기존 정보의 탐색·표현 개선을 우선한다.

### 꿀팁

현재는 선택한 월령과 별개인 무작위 팁 카드가 시간표·식단보다 먼저 보인다. 6개월 화면에서도 영아 산통 팁이 첫 카드로 표시된 사례가 있다. 그 팁의 의학적 적합성 판정과 별개로, 월령 필터가 무엇을 바꾸는지 분명하지 않다.

- 시간표/식단을 먼저 보여주고 일반 팁은 뒤에 배치한다.
- 월령에 맞는 팁과 공통 팁을 구분해 대상이 이해되게 한다.
- '새로고침하면 새 팁' 대신 화면 안 '다른 팁 보기'를 제공한다. 시간표의 펼친 상태를 잃지 않는다.
- 식단은 '오늘' 또는 사용자가 고른 요일을 명확히 표시한다. 초기 선택이 항상 월요일인 현재 동작을 정리한다.
- 시간표는 참고 예시임을 보이고 사용자의 실제 일지처럼 오해되지 않게 한다.
- 선택한 식단과 관련된 재료·이유식 안내를 백과 상세로 연결한다.

### 완료 기준

- 사용자가 선택한 월령이 어떤 콘텐츠에 적용되는지 설명할 수 있다.
- 건강 질문에서 답변과 적용 연령을 함께 찾을 수 있다.
- 일반 팁을 바꾸거나 상세를 다녀와도 선택 요일/월령과 펼친 상태가 유지된다.

## 8. STEP 6 — 설정·가족 공유·저장 상태

### 현재 관찰

- 설정에는 계정·현재 아기·프로필 편집·환경·공유·삭제가 긴 화면에 이어진다.
- 아기 전환은 설정 안에 있어 기록 중 전환하기 번거롭다.
- '로그인', '공유 연결', '기기에 저장', '백업'의 관계가 충분히 설명되지 않는다.
- 공유 참여가 현재 기록을 어떻게 바꾸는지, 연결을 해제하면 누가 무엇을 볼 수 있는지 설명과 실제 동작을 함께 보완해야 한다.

### 변경안

- 설정을 **내 계정 / 아기 관리 / 가족과 공유 / 앱 환경 / 데이터 관리**로 묶는다.
- 홈과 기록 상단에도 현재 아기 전환을 제공하고 이름·사진·선택 표시를 유지한다.
- 저장 상태를 '기기에 저장됨', '백업 중', '백업 완료·시각', '백업 실패·다시 시도'로 구분한다.
- 계정 로그인과 특정 아기의 공유 참여를 별개 단계로 설명한다.
- 공유 참여 전 아기 이름·대상·가져올 기록과 기존 기록의 처리 방식을 확인한다. 다른 아기의 기록까지 초기화되면 안 된다.
- 초대코드 복사 시 완료 피드백, 만료/취소 기능, 참여 가족 목록을 단계적으로 제공한다. 만료/가족 목록은 새로운 서버 기능이 필요한 후속 항목이다.
- '공유 해제', '이 기기에서 기록 삭제', '서버 기록 삭제', '계정 탈퇴'를 정확한 범위로 구분한다.
- 실패를 성공으로 표시하지 않는다. 오류를 닫아도 다시 시도하거나 기록을 확인할 수 있어야 한다.

### 완료 기준

- 사용자가 현재 어떤 아기의 기록을 어느 기기/가족과 공유하는지 확인할 수 있다.
- 같은 계정으로 다른 기기에서 로그인했을 때 실제 복원이 검증된 후 백업 완료 안내를 사용한다.
- 공유 해제 후 다시 자동 공유되지 않고, 삭제 안내의 범위와 실제 파기 동작이 일치한다.

## 9. STEP 7 — UI/UX QA와 완료 판정

아래는 실행할 검증 계획이다. 이번 추가 분석에서 모두 수행했다는 의미가 아니다. 시간·성공률의 현재 수치는 측정하지 않았다.

| 과제 | 확인할 행동 | 완료 기준 |
|---|---|---|
| 첫 방문 | 둘러보기, 아기 등록, 홈 이해 | 도움 없이 시작하고 저장 방식을 설명할 수 있음 |
| 정보 찾기 | 백과→수면/이유식/건강 글, 검색→본문 | 숨은 메뉴를 찾느라 막히지 않고 본문까지 도달 |
| 탐색 복귀 | 상세→뒤로, 하단 탭 변경 후 복귀 | 월령·주제·검색어·스크롤을 잃지 않음 |
| 성장 기록 | 추가→범위 오류 수정→저장→수정→삭제 취소 | 데이터와 날짜가 맞고 중복/유실 없음 |
| 아기 전환 | A와 B의 차트·접종·발달을 반복 전환 | 현재 아기의 기록만 표시 |
| 접종 기록 | 날짜를 지정해 완료·수정·취소 | 차수·날짜·홈 요약이 일치 |
| 건강 글 | 검색·답변·대상 연령·출처 확인 | 정보 열람과 현재 상태 판정을 혼동하지 않음 |
| 생활 자료 | 월령·요일 변경, 팁 교체 | 무관한 화면 상태 초기화 없이 이용 |
| 실패 복구 | 오프라인·연결 실패·백업 실패 | 원인과 다음 행동이 보이고 입력을 잃지 않음 |
| 모바일 입력 | iOS/Android 키보드·한 손 조작 | 버튼이 가려지지 않고 입력/저장 완료 |
| 접근성 | 글자 200%, 스크린리더, 키보드, 줄인 모션 | 라벨·순서·포커스·가독성을 유지 |
| 화면 크기 | 360/390/430px, 큰 글자, 가로/넓은 화면 | 주요 행동이 잘리거나 하단 바에 가려지지 않음 |

초기 사용자 확인에서는 부모에게 위 주요 과제를 제공하고, 막힌 위치·잘못 누른 곳·도움 요청·완료 여부·소요 시간을 기록한다. 개선 전후를 같은 과제로 비교한다. 디자인 점수나 만족도 숫자를 관찰 없이 부여하지 않는다.

### 상태별 공통 문구 예시

| 상황 | 제안 문구/행동 |
|---|---|
| 측정 기록 없음 | '아직 측정 기록이 없어요' · '첫 기록 추가' |
| 콘텐츠 서버 실패 | '정보를 불러오지 못했어요' · '다시 시도' |
| 검색 일치 없음 | '이 검색어로 찾은 글이 없어요' · 주제 제안 |
| 기기에만 저장 | '이 기기에 저장했어요' · 백업 설명 |
| 클라우드 백업 실패 | '기기에는 저장됐지만 백업하지 못했어요' · '다시 시도' |
| 기록 삭제 | '기록을 삭제했어요' · '되돌리기' — 복원 기능 구현 후 사용 |
