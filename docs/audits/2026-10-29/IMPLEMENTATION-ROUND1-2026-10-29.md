### 브라우저에서 확인한 사용자 흐름

- 홈에서 성장 기록 추가 시트를 직접 열기.
- 잘못된 키 10cm 입력 시 해당 필드 오류 표시.
- 가상 B의 키 59.3cm/몸무게 5.4kg 저장 후 차트·기록 목록 반영.
- 같은 기록을 60.1cm로 수정하고, 기록 수는 1건 유지.
- 삭제 확인을 열고 '기록 유지'로 취소해 기록 보존.
- 홈의 아기 선택에서 A는 58.4cm, B는 60.1cm로 분리 표시.
- 홈 수면 링크가 `tab=sleep&month=2`로 이동.
- 백과에서 선택 월령을 검색 링크에 유지.
- 온라인 콘텐츠 조회가 실패해도 '양치' 정적 가이드 검색 결과 3건 표시.
- 검색 결과 전체 본문 열기와 '검색 결과로' 복귀 시 검색어 유지.
- 별도의 localhost 저장 영역에서 등록 전 둘러보기→게스트 백과→수면 가이드 접근.
- 가상 접종 기록에 실제 접종일을 지정해 저장하고, 이번 시기 미완료 수가 5회→4회로 갱신.
- 밝은/어두운 테마 확인. 390px QA 화면에서 홈 주요 기록 버튼은 위쪽 약 222~318px에 위치.

이번 재검증의 실제 확인 폭은 390px다. 360/430px 설정 요청이 브라우저의 실제 innerWidth 변경으로 확인되지 않아 해당 폭의 신규 QA 통과로 집계하지 않았다. 실기기 키보드·확대·스크린리더·다른 화면 크기의 전수 검증은 남아 있다.

검증에는 가상 아기와 로컬 QA 프록시를 사용했다. 프록시의 DB 쓰기 요청은 0건으로 확인했고, 운영 DB에 테스트 기록을 생성하거나 수정하지 않았다. `http://127.0.0.1:3219/`는 이 로컬 QA 구성의 미리보기다.

## 아직 남은 작업

- STEP 1: 기존 가이드 전체의 글자 크기/터치 영역, 온보딩 등 반복 모션의 전면 정리.
- STEP 3: 다양한 뒤로 가기/긴 목록/스크롤 복원 조합과 실제 Supabase 검색 응답 검증.
- STEP 5: 의료 콘텐츠의 항목별 출처·검수일·전문가 검수. 위험 문구와 발열 기준 정합성은 기존 분석의 공개 전 해결 항목으로 유지.
- STEP 6: 설정 화면 전체 재구성, 아기별 실제 백업 상태/재시도 표시, 가족 목록·초대 만료/취소, 로그인 후 기존 기록 복원, 안전한 동시 수정 동기화.
- STEP 7: 실제 사용자 과제 관찰, iOS/Android 실기기, 접근성·PWA·오프라인 업데이트 검증.
- 기존 관리자 고정 인증, 실제 DB RLS/소유권, 계정 삭제 시 파기 절차는 이번 UI 변경으로 해결됐다고 볼 수 없다.
- 현재 설정된 원격 Supabase 주소는 이전 분석에서 DNS 조회에 실패했다. 실제 로그인/클라우드 공유 완료는 검증하지 않았다.
- 기존 여러 아기의 소유자 없는 기록은 자동으로 특정 아기에게 배정하지 않는다. 데이터는 보존하고, 향후 명시적 소유자 확인/이관 화면이 필요하다.
